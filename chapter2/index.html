LLM 本質：你在跟什麼東西說話

在你開始下指令之前，先搞清楚：坐在螢幕另一邊的，到底是什麼東西。它不是人，也不是搜尋引擎，它是一台「文字接龍機器」。

上一章說，用 AI 做出別人能用的工具，難的不是叫它動手，是做完之後還改得動、修得好，靠的是知道邊界。邊界要講給 AI 聽，講之前，先認識聽的那一方。這章講它怎麼運作、它記得多少、每一句話花多少錢；懂了這些，下一章學下指令才知道為什麼要那樣講。

LLM 的本質：一台超級文字接龍機器

Claude、ChatGPT、Gemini 這類 AI 叫 LLM，全名是 Large Language Model（大型語言模型）。聽起來很厲害，但它做的事情本質上非常單純：根據你前面說的話，預測「下一個字」最可能是什麼。

你跟它說「今天天氣」，它不是去查氣象局，而是根據它讀過的大量文字，判斷「今天天氣」後面最常接什麼字，可能是「很好」、「不錯」、「真熱」。然後它從這些可能的答案裡挑一個。

接著，它拿「今天天氣很好」這整句話，再預測下一個字。如此反覆，一個字接一個字，直到它覺得該停了。

比喻：讀過全世界圖書館的鸚鵡

想像有一隻鸚鵡，它讀過非常多的書、網頁、對話紀錄和程式碼。你問它什麼，它都能說出一段聽起來很有道理的話。

但是，它並不「理解」它在說什麼。它不知道「悲傷」是什麼感覺，它只知道「悲傷」這個詞後面，通常會接「難過」、「流淚」、「心痛」這些字。

說出來的話很有道理，但它不真的懂。這就是 LLM 最重要的本質。

所以，當 LLM 給你一個錯誤的答案，它不是在「騙你」，它只是接龍接錯了。就像鸚鵡不是故意說錯話，它根本不知道什麼是對什麼是錯。麻煩的是，它接錯的時候，講得跟接對的時候一樣有自信。這個現象有個專有名詞，叫 Hallucination（幻覺）：AI 一本正經地講錯。

重要觀念
LLM 本身的知識全部來自「訓練資料」，也就是它被餵過的那些文字。訓練資料有截止日期，截止之後發生的事它不知道。

現在很多 AI 工具會幫它接上「查資料」的能力。Claude Code 就可以上網搜尋、讀官方文件、查錯誤訊息，也會讀你資料夾裡的檔案。但它查到什麼、讀到什麼，還是要經過「接龍」這一關才講給你聽，所以重要的事，請它附上出處。

訓練資料決定一切

文字接龍接得好不好，完全取決於這台機器「讀過什麼」。這就是訓練資料（Training Data）的重要性。兩個例子可以幫你理解：

例子一：白日依山盡

在台灣只要講「白日依山盡」，幾乎每個人都會接「黃河入海流」。為什麼？因為受過中文教育的人都讀過這首詩，腦中早就建立了這個連結。

但如果這是一個沒讀過中文資料的模型，它可能覺得「白日依山盡」後面接「早餐正好吃」也很合理，然後就這樣輸出了。它不是故意搞笑，它只是從來沒讀過唐詩，所以不知道「正確答案」是什麼。

這就是訓練資料的差異。同樣的文字接龍機器，餵不同的資料，產出完全不同的結果。
例子二：孫悟空

你跟在華人文化裡長大的人講「孫悟空」三個字，腦中自然浮現一隻猴子拿著金箍棒，旁邊還有唐僧和白馬。這個畫面是《西遊記》幾百年的文化沉澱。

但你跟一個從小看日本動漫的美國人說「Son Goku」，他腦中浮現的可能是《七龍珠》裡那個金色頭髮的超級賽亞人，完全不同的東西。

LLM 也是一樣，它「腦中浮現什麼」，取決於訓練資料裡有什麼。一個大量讀日本動漫資料的模型，和一個大量讀中國古典文學的模型，對「孫悟空」的理解天差地別。

這帶出一件很實際的事：你公司的事，它沒讀過。訓練資料裡不會有你的客戶、你的報價規則、你家系統哪一張表不能動。它會讀你給它的檔案，也會上網查，但「哪些不能動」這種只在你腦子裡的東西，要你講。

RAG：讓 AI 從閉卷考變開書考

RAG 的全名是 Retrieval-Augmented Generation（檢索增強生成）。聽起來很學術，白話講就是：讓 AI 先翻你的資料，再回答問題，不是只靠它自己記住的東西。

比喻：閉卷考 vs. 開書考

沒有 RAG 的 AI 就像在考閉卷考：它只能靠訓練時記住的知識來回答。如果這個知識它沒學過（比如你公司內部的 SOP、最新的法規修訂），它就只能瞎猜，或說「我不知道」。

有 RAG 的 AI 就像在考開書考：回答之前，它會先去翻你提供的「參考書」（可以是你的文件、資料庫、知識庫），找到相關段落之後，再根據這些資料組織答案。

同一個學生，開書考通常考得比閉卷考好。但書要給對：參考書本身寫錯，它就照著錯的抄。

RAG 跟前面講的訓練資料直接相關：AI 沒學過的東西，如果你不即時補充給它，它就只能用「文字接龍的直覺」去猜，而猜出來的東西，就是 Hallucination。

白話總結
訓練資料 = AI 的長期記憶（學校學的）。RAG = AI 的即時參考書（考試時翻的）。兩者結合，AI 才能又有基礎知識、又能處理它沒見過的新資訊。

平常用 Claude Code 時，你把檔案、截圖、錯誤訊息、公司的規矩交給它，就是在做最簡單的「開書考」。它不知道的，要你給。

各家模型有什麼不同

市面上有好幾家在做 LLM，最常聽到的是 OpenAI 的 GPT（ChatGPT 背後的模型）、Anthropic 的 Claude、Google 的 Gemini。它們的原理差不多，都是文字接龍，但各有擅長的地方。

比喻：三個不同性格的顧問

下面是作者自己用下來的印象，不是評測結果；各家每隔幾個月就出新版，印象也會跟著變。

GPT（OpenAI）像一個什麼都會一點的萬用顧問。你問什麼它都能答，生態成熟、外掛多，但有時候會太自信，明明不確定的事也講得斬釘截鐵。

Claude（Anthropic）像一個謹慎的技術顧問。它擅長讀長文件、寫程式碼、做分析，不確定的事比較會跟你說「我不確定」。Claude Code 用的就是 Claude 模型。

Gemini（Google）像一個資料量很大的研究員。它能接上 Google 搜尋，擅長整合各種來源的資訊，看圖、看影片、聽聲音這類多模態的能力也強。

沒有「最好」的模型，只有「適合你當下需求」的模型。用 Claude Code 做專案，背後就是 Claude；你要選的不是哪一家，而是用大一點還是小一點的那款（下面會講）。
關於本網站
本網站內容通用於所有 LLM，不限特定廠商。文字接龍、Context Window、Token 這些觀念，不管你用哪家都適用。案例採用 Anthropic 的 Claude，是因為作者的使用經驗最多。

模型大小就是物理規律

Anthropic（Claude）目前有幾個值得注意的特點：

  • 1M Context Window：Claude 目前各款模型都支援 100 萬 token 的上下文視窗，一次能攤開的資料量很大（2026 年 11 月官方模型頁）。
  • 讓 AI 操作電腦：Anthropic 很早就推出 Computer Use，讓 AI 看螢幕、點滑鼠、打字。Claude Code 的桌面版也能用。不過在這本書的順序裡它排最後：有官方 CLI 先用 CLI，沒有才裝 MCP，網頁交給瀏覽器工具，都不行才用 Computer Use（第十章 Claude Code 怎麼用）。
  • 安全規矩比較嚴：有些事它會拒絕，或停下來先問你。有時候會讓你覺得「怎麼這麼囉嗦」，但這是 Anthropic 的設計取向，既是特色也是門檻。

但是，這不代表 Anthropic 就特別優秀。

如果你用 Anthropic 最便宜（最小）的那款模型，它的效果通常比不上其他家的中階模型。這不是品牌問題，這是物理規律：同一個世代裡，模型越大、參數越多，能力通常越強。就像一台 2 公升引擎的車，不管品牌多好，很難跑贏對手的 5 公升引擎。選模型的時候，品牌忠誠度遠不如「選對大小」來得重要。

大的模型比較聰明，也比較貴、比較慢；小的便宜、快，適合簡單、大量的工作。在 Claude Code 裡打 /model 就能換，難的事用大的，例行的事用小的。

Context Window：AI 的「桌面大小」

Context Window（上下文視窗）是 LLM 最重要的概念之一。簡單說，它就是 AI 在一次對話中「能同時攤開多少東西」的上限。

比喻：你的辦公桌

想像你在處理一個案子，你的辦公桌就這麼大。你可以攤開幾份文件、幾張圖表，同時對照著看。但如果文件太多，桌子放不下，你就得把舊的收起來，才能放新的。

AI 的 Context Window 就是這張桌子。你說的話、它的回答、它讀過的檔案、背景設定，全部攤在這張桌上。桌子越大，能同時看的資料越多。桌子滿了，就得收掉一些：有的工具會把最舊的直接推掉，Claude Code 則是把前面的對話壓成摘要。

這個「桌子」的大小用 Token 來衡量（Token 是什麼，這章後面會講）。以 Claude 為例，目前各款模型都是 1,000,000 tokens（100 萬）。其他家的數字也一直在往上加，而且常隨新版調整，要知道確切的數字，查各家的官方模型頁。

聽起來很多？但實際上消耗速度比你想像的快。因為 Context Window 裝的不只是你說的話，還包括：

  1. 系統指令（System Prompt）：告訴 AI「你是誰、該怎麼做事」的背景設定
  2. 你的每一句話：包括你之前所有的對話歷史
  3. AI 的每一句回覆：它自己說過的話也算
  4. 程式碼、文件內容：如果你叫它讀檔案，檔案內容也會佔空間；它跑指令印出來的結果也算
  5. 每次開工先讀的說明檔：Claude Code 會先讀專案裡的 CLAUDE.md 和它自己記的筆記（下一章會講）

現在的桌子已經很大，而且 Claude Code 快滿的時候會自動整理，真的放不下的情況不常見。但桌子大，不代表可以亂堆：

  • 每一輪都要重讀整張桌子。AI 不會「記得」上一句，每次回答，都是把整段對話重新送一次。對話越長，每一句越貴。
  • 堆太多雜物，它會分心。三件不相干的事、兩次失敗的嘗試都還攤在桌上，它每次都會看到，回答就容易被帶歪。

回答變得前後矛盾
你說「照之前的格式」，
它卻做出完全不同的格式
程式碼開始出現重複或遺漏
桌面清爽的狀態
AI 記得你這次的所有需求
回答邏輯連貫、前後一致
能引用你之前提過的細節

上下文壓縮與對話分支

既然桌子會滿，有沒有辦法「自動整理桌面」？有的。Claude Code 有幾個機制可以幫忙：

上下文壓縮（Compaction）：對話太長、快要塞滿 Context Window 時，Claude Code 會自動把前面的對話壓成摘要，騰出空間繼續做。就像你把桌上的文件整理成一頁摘要，騰出空間放新東西。你不需要手動觸發，它會自己判斷什麼時候該壓。想自己決定什麼時候壓、要留哪些重點，可以打 /compact，後面加一句「保留 API 的修改和測試指令」這類說明。

要注意的是，官方文件也寫明：摘要會留下你的要求和關鍵的程式碼，但對話很前面交代的細節可能在壓縮時遺失。所以每次都要遵守的規矩，不要只講在對話裡，要寫進 CLAUDE.md（下一章）。

對話分支（Fork）：你可以從目前的對話「分叉」出一條新的分支。打 /branch，它會把到目前為止的對話複製成一個新的對話，原本那條原封不動留著。就像遊戲裡的存檔點：先存一份，再去試另一條路，走錯了，原本的存檔還在。

倒回去（Rewind）：打 /rewind，或在輸入框是空的時候連按兩次 Esc，可以選一句你說過的話，把對話、程式，或兩個一起倒回那句之前。

實用場景
你請 AI 用方案 A 做了一個功能，做到一半覺得方案 B 可能更好。這時候先 /branch 留住方案 A 的對話，再在新的分支裡 /rewind 回到「還沒開始做」的那一句，改走方案 B。方案 A 的對話還在，隨時可以回去看。

但要記得：對話可以分兩條，資料夾裡的檔案只有一份。倒回程式碼，方案 A 改過的檔案也會跟著退回。想把方案 A 的程式也留著，先請 Claude 用 Git（版本控制）存一個版本再分叉。這些指令細節在第十章 Claude Code 怎麼用。

對話越長，品質越爛

就算桌子還沒完全滿，AI 的表現也會隨著對話變長而下降。Anthropic 的官方文件把這個現象叫 context rot（上下文腐壞）：放進去的東西越多，它找得準、記得住的能力越差。也有人叫它 Context Fragmentation（上下文碎片化）或 Context Degradation（上下文退化），講的是同一件事。

比喻：堆滿東西的桌子

你的桌子雖然還有空間，但上面堆了 100 份文件。你要找其中一份的某個數字，得翻半天。就算找到了，你可能也忘了剛剛另一份文件上寫了什麼。

AI 也一樣。當 Context Window 裡塞了太多東西，各種需求、修改紀錄、程式碼、錯誤訊息，它就越來越難「找到重點」。它不是忘了，而是被噪音淹沒了。

實際的症狀包括：

  • 你一開始提的需求，聊到後面它已經「沒在管了」
  • 你明明修正過的 bug，它又做回原本有問題的版本
  • 回答開始變得泛泛的，不夠具體
  • 程式碼的風格、命名規則開始不一致

何時該開新對話

當你感覺到上面任何一個症狀，就是該開新對話（新 Session）的時候。在 Claude Code 裡打 /clear 就是開一場全新的對話；舊的不會不見，用 /resume 找得回來。以下是一些經驗法則：

情境 建議
對話已經拉得很長，回頭找東西要捲很久 開新對話，把重要的結論整理成一段摘要貼給它
主題已經換了（從 A 功能跳到 B 功能） 開新對話，一個對話只做一件事
AI 開始忘記之前的決定 開新對話，在開頭摘要之前的重要決定
同樣的規矩你已經講了好幾次 寫進 CLAUDE.md，以後每次開工它都會先讀（下一章）
單純修一個小 bug 可以繼續；但同一件事糾正兩次還不對，不要糾正第三次，/clear 之後把剛剛學到的寫成一句更完整的指令重來

最後一條是官方使用建議（Best practices）的意思：糾正兩次還錯，對話裡已經堆了兩次失敗的嘗試，它每次都會重讀；清掉重來，加一句更好的指令，通常比較快。

實用建議
開新對話不代表「砍掉重練」。你可以在新對話的第一句話裡，把之前的重要結論、架構決定、檔案路徑整理成一段摘要貼上去，或者叫舊對話的 Claude 先幫你寫好這段摘要。這比讓 AI 在很長的對話裡自己翻找有效太多了。

Token：AI 的計費單位

前面一直提到 Token，到底 Token 是什麼？

Token 是 AI 處理文字的最小單位。你可以把它想像成「AI 版的音節」。它不是一個字、也不一定是一個詞，而是 AI 自己切割文字的方式。

比喻：寄包裹的重量計費

就像寄國際包裹用「公斤」計費，AI 用 Token 計費。你寫給它的每一個字都有重量，它回覆你的每一個字也有重量。來回越多輪，包裹越重，費用越高。

而且 AI 不只是秤你寄出去的（Input Token），還秤它寄回來的（Output Token）。你講的多花錢，它回的長也花錢。

不同的內容，切法不一樣：

內容 怎麼切 要知道的
英文 常見的單字常常整個是一塊 長的、少見的字會被切成好幾塊
中文 一個字可能是一塊，也可能被切成好幾塊 同一句話用掉多少，每家、每一代模型都不一樣
程式碼 符號、空格、縮排都算 一大段程式碼或一長串錯誤訊息，很快就吃掉桌面

想知道一段文字確切是幾個 Token，各家都有官方的計算工具；平常不用算，知道「越長越貴」就夠了。

為什麼要在乎 Token？因為：

  1. Token = 錢：用 API 的話，是照 Token 數量收費；用訂閱方案的話，Token 用得越多，越快碰到用量上限。在 Claude Code 裡打 /usage 可以看用了多少。
  2. Token = 桌子空間：前面講的 Context Window 就是用 Token 來衡量大小的。你浪費 Token 在無意義的對話上，就是在佔桌子空間。
  3. Token = 時間：Token 越多，AI 處理的時間越長，回覆越慢。
浪費 Token 的做法
你：「嗯……我想想看……
那個功能……就是……
你知道那種可以讓使用者……
算了我重新說好了」

短，資訊完整且精確
Token 省錢公式
說清楚 + 說具體 + 一次到位 = 最省 Token。

每多一輪來回對話，Token 消耗是「累加」的，因為 AI 每次回覆都要重新讀一遍整個對話歷史。第 1 輪它讀 1 段，第 10 輪它讀 10 段，第 30 輪它讀 30 段。所以同樣的事情，1 輪搞定跟 10 輪搞定，差距會越滾越大。

Claude Code 會用「快取」讓重讀前面的內容便宜一些，但只在短時間內有效，而且快取省的是錢，不會讓那些內容少佔桌面。

節省 Token 的實用工具

除了養成「說清楚、說具體」的習慣之外，還有工具可以幫你精簡輸入：

  • Typeless：一個語音輸入工具。你用講的，它把「嗯」、「那個」、「就是」這類填充詞自動刪掉，整理成乾淨的文字，再貼給 AI。上面那段「嗯……我想想看……」就是它會幫你砍掉的東西。電腦和手機都有，適合想到什麼就講、不想打字的人。

這章帶走什麼

  1. LLM 的本質是文字接龍。它不理解，它只是預測下一個字。所以它會 Hallucination（一本正經地講錯），而且講錯時跟講對時一樣有自信。
  2. 訓練資料決定一切。同樣的接龍機器，餵不同資料就有不同結果。你公司的事它沒讀過，要你給。
  3. RAG 讓 AI 從閉卷考變開書考。讓 AI 先翻你的資料再回答，可以減少幻覺；前提是給它的資料是對的。
  4. 不同模型有不同個性。GPT 萬用但太自信、Claude 謹慎擅長程式碼、Gemini 多模態強但有時不聚焦。這是作者的印象，版本一換就會變。
  5. 模型大小是物理規律。品牌忠誠度不如選對大小，小模型就是很難跑贏大模型。
  6. Context Window 是 AI 的桌面。桌子現在很大，快滿時 Claude Code 會自動壓縮；想保留某個時間點，用 /branch，想倒回去，用 /rewind。
  7. 對話越長品質越差。這叫 context rot，不是 bug。換主題就 /clear，糾正兩次還錯就重寫一句完整的指令。
  8. Token 是計費單位。講越多、AI 回越多，就越花錢也越慢。說清楚、說具體、一次到位才省。

理解了這些，你就知道為什麼不能隨便跟 AI 閒聊：每一句話都有成本，而且你沒講的，它只能猜。下一章，我們來學怎麼用最少的話，把最多的資訊傳達給 AI。

可以直接抄
要它照你的資料回答：
「這是我們公司的報價規則（貼上或給檔案路徑）。照這份回答，裡面沒寫的就說不知道，不要自己補。」

怕它講錯：
「你剛剛說的那個規定，出處是哪裡？給我官方頁面的連結；查不到就直接說查不到。」

要開新對話之前：
「把目前已經決定的事、改過的檔案、還沒做完的部分，整理成一段摘要給我，我要開新對話接著做。」

要它記住每次都要遵守的事：
「把『金額只能在後端算』這條加進 CLAUDE.md。」
