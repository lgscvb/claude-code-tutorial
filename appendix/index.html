常見問題

正文到第十八章為止。這一頁收的是非工程師動手時常卡住、常問的四件事：錯誤訊息怎麼讀、金鑰為什麼不能寫在程式裡、Git 到底是什麼、Claude 提到的套件是什麼。每一題最後都會回到同一件事：知道邊界在哪。

錯誤訊息怎麼讀：不要看到紅字就慌

很多人看到一大片紅字就慌了。其實你只要找三個資訊：

  1. 錯誤類型：哪一類的錯（通常在第一行或最後一行）
  2. 錯誤原因：發生了什麼事
  3. 出錯位置：哪個檔案的第幾行

錯誤會出現在兩個地方。指令出的錯在終端機（打字下指令的那個視窗），Claude 自己跑的指令，錯誤它自己看得到。網頁上的錯在瀏覽器的「主控台」（Console）：在頁面上按右鍵選「檢查」，切到 Console 分頁就看得到。這種要你貼給它，或讓它用 Claude in Chrome 自己去看。

例一：網頁上的錯（JavaScript）

報價單按下「計算」沒反應，主控台出現這段：

Uncaught TypeError: Cannot read properties of undefined (reading 'price') at calcTotal (quote.js:42:25) at HTMLButtonElement.handleSubmit (quote.js:18:5)

拆開來看：

部分 告訴你什麼
TypeError 錯誤類型：類型錯誤，拿一個東西去做它做不到的事
Cannot read properties of undefined (reading 'price') 錯誤原因：程式要讀某個東西的 price（價格），但那個東西是空的（undefined）。常見是品項沒選到，或資料還沒載進來
quote.js:42:25 出錯位置：quote.js 這個檔案的第 42 行
下面那幾行 at 一路怎麼走到這裡：按鈕被按下 → handleSubmit → calcTotal 出事。這一串叫 stack trace

例二：後端的錯（Python）

後端程式常用的 Python，錯誤長得不太一樣：

Traceback (most recent call last): File "/app/routes/user.py", line 42, in get_user result = db.query("SELECT * FROM users WHERE id = " + user_id) File "/app/database.py", line 15, in query cursor.execute(sql) TypeError: can only concatenate str (not "int") to str
部分 在哪裡 告訴你什麼
TypeError 最後一行的開頭 錯誤類型：類型錯誤（文字和數字不能直接接在一起）
can only concatenate str... 最後一行的說明 錯誤原因：程式想把「文字」（str）和「整數」（int）接在一起
user.py, line 42 中間的 Traceback 出錯位置：user.py 這個檔案的第 42 行
Traceback 中間那幾行 第 2 到 5 行 Stack trace：從哪裡開始、經過哪裡、在哪裡出事

順帶一提：這個例子把使用者給的編號直接接進 SQL 句子裡，就算不報錯也是危險的寫法（別人可以在編號裡夾帶指令）。Claude 修這種錯時，請它改成「帶參數的查詢」，不要只是把數字轉成文字了事。

Stack trace＝麵包屑

比喻：追監視器畫面。

Stack trace 像一串監視器畫面，告訴你「從 A 房間出發 → 經過 B 走廊 → 在 C 房間出事」。

先找「在哪裡出事」，再往回看「怎麼走到那裡」。大部分時候，只看出事的那幾行就夠了。

要注意方向。瀏覽器的 JavaScript 錯誤（例一），錯誤寫在最上面，往下是一路怎麼走到那裡的。Python（例二）剛好反過來：開頭寫著 Traceback (most recent call last)，意思是「最後發生的寫在最下面」，錯誤在最後一行，上面是路徑。分不清的時候，整段貼給 Claude，它分得出來。

常見錯誤類型速查

錯誤類型 白話意思 常見原因
TypeError 類型搞錯了 把數字當文字用、對空的東西讀資料
SyntaxError 語法寫錯了 少了括號、多了逗號、引號沒成對、關鍵字拼錯
ReferenceError 找不到這個名字 名字打錯、該先載入的 JS 檔或模組沒載到
401 Unauthorized 不知道你是誰 沒登入、金鑰填錯或過期
403 Forbidden 知道你是誰，但你沒有權限 帳號權限不夠、存取規則擋下來、IP 被擋
404 Not Found 找不到 網址打錯、檔案被刪了或放錯資料夾、路由沒設定
429 Too Many Requests 太頻繁，被擋了 短時間內呼叫同一個服務太多次
500 Internal Server Error 伺服器那邊出錯 後端程式有 bug、資料庫連不上
CORS 錯誤 跨網域被擋 網頁和後端不在同一個網域，後端沒開放這個網域來呼叫
ERR_CONNECTION_REFUSED、ECONNREFUSED 連線被拒絕 要連的服務沒開，或 port（連接埠號碼）打錯。常見於在自己電腦上預覽時，預覽伺服器沒開
EADDRINUSE、address already in use 這個 port 已經有人在用 預覽伺服器已經開著一個，又開了第二個。關掉舊的，或換一個 port
command not found 終端機找不到這個指令 這個工具還沒裝、名字打錯，或剛裝好但終端機還沒重開
怎麼跟 Claude 求助
看到錯誤訊息，整段複製貼給 Claude，再補一句你剛剛做了什麼（「按下計算之後」「部署完打開首頁」）。不要只說「它壞了」或「跑不動」。

錯誤類型、出錯位置、一路怎麼走到那裡，它要的線索都在那段字裡。你不用看懂，貼完整就好。
修錯的時候，邊界也要講
錯誤訊息消失，不等於問題修好了。AI 修錯有幾種做法會留後患，先講好不准這樣做：
- 把錯誤藏起來：整段包起來、出錯就不吭聲。紅字不見了，東西照樣是壞的
- 把檢查拿掉：「欄位不能空白」的檢查報錯，就把檢查刪了
- 順手改一大片：修一個按鈕，連帶改了三個檔案、加了一個欄位

所以先叫它講原因、講要改哪幾個檔，你點頭再改。改完再按一次同一個按鈕，確認真的好了。

.env 環境變數：金鑰放哪裡

為什麼金鑰不能寫在程式碼裡

金鑰（API key）是你的程式登入別的服務用的那串字，等於密碼。想像一下：你的程式裡直接寫著資料庫密碼，然後你把程式推上 GitHub 的公開 repo（放程式碼的地方）。這下誰都看得到，包括專門在網路上找金鑰的自動程式。

私人 repo 也不要放。分享給外包、換一台電腦、哪天改成公開，金鑰就跟著出去了。GitHub 對推到公開 repo 的內容，預設會擋下看起來像金鑰的東西（push protection），但那是最後一道網，不能靠它。

比喻：把保險箱密碼寫在大門上。

你不會把家裡保險箱的密碼寫在大門上。把金鑰寫在程式碼裡再上傳，就是在做這件事。門是透明的，路過的人都看得到。

.env 是什麼

.env 是「環境變數檔」，白話說就是密碼本。它是一個純文字檔，把金鑰集中放在這裡，程式要用的時候來這裡讀：

# .env 檔案的內容長這樣：

SUPABASE_URL=https://你的專案.supabase.co
SUPABASE_SECRET_KEY=這裡填真的金鑰
STRIPE_SECRET_KEY=這裡填真的金鑰
LINE_CHANNEL_SECRET=這裡填真的金鑰

重點：.env 只放在你的電腦上，不上傳到 GitHub。做法是在 .gitignore（Git 的「不要管這些檔案」清單）裡加上 .env，Git 就不會把它收進去。

放在 Cloudflare 上跑的後端程式（Workers）也一樣：在自己電腦上測試時，金鑰放 .dev.vars 或 .env，兩個都不進 Git；上線用 wrangler secret put 金鑰名字 存到 Cloudflare 那邊。

.env.example 是什麼

.env.example 是「密碼本的模板」：告訴別人要填哪些金鑰，但不放真的值。

.env（真的密碼本，不上傳）
SUPABASE_URL=https://abcd.supabase.co
SUPABASE_SECRET_KEY=（真的金鑰）
STRIPE_SECRET_KEY=（真的金鑰）
LINE_CHANNEL_SECRET=（真的金鑰）
.env.example（模板，可以上傳）
SUPABASE_URL=
SUPABASE_SECRET_KEY=
STRIPE_SECRET_KEY=
LINE_CHANNEL_SECRET=

# 只有名稱，沒有值

頁面上的金鑰：前後端的線畫在這裡

純靜態頁面沒有地方藏 .env：頁面上的 JS，打開網頁的人全都看得到。所以金鑰分兩種：

  • 可以放在頁面上的：Supabase 的 publishable key（sb_publishable_ 開頭，舊名 anon key）。它本來就設計成給頁面用，資料能不能讀、能不能改，靠每張表的存取規則（RLS）把關。所以每一張表都要開 RLS。
  • 只能放後端的：Supabase 的 secret key（sb_secret_ 開頭，舊名 service_role key），它會跳過存取規則；還有其他服務的密鑰（像 Stripe 的 secret key）。這些只能存在 Cloudflare Workers 或 Supabase Edge Functions 的 secret 裡，不能出現在頁面上。Supabase 的新版 secret key 放在瀏覽器裡本來就用不了，會被擋下來。

Supabase 官方文件寫明，舊名的 anon、service_role key 預計在 2026 年底前淘汰。Claude 寫的程式如果還在用舊名字，請它換成新的。這條線怎麼畫，第十六章 前後端邊界有完整的講法。

必記原則
.env＝密碼本，只存在你的電腦上，不上傳。
.env.example＝密碼本模板，告訴別人要填什麼，可以上傳。
頁面上只能放 publishable key，其他金鑰一律放後端。

Claude 寫的程式裡如果直接出現一串真的金鑰（像是 sb_secret_、sk_live_ 開頭的字串，或是網址裡夾著密碼），或是把 secret key 寫進頁面的 JS，馬上叫它移到後端的 secret。

金鑰已經外流了怎麼辦

發現金鑰已經推上 GitHub，或出現在頁面上，順序是這樣：

  1. 先到那個服務的後台，把這把金鑰作廢、換一把新的。這一步最急，因為別人可能已經抄走了。
  2. 再把程式裡的金鑰拿掉，改成讀 .env 或後端的 secret，新金鑰放進去。
  3. 只刪掉那一行不夠。Git 會留下每一次修改的紀錄，舊的紀錄裡還找得到。所以第一步的作廢不能省。

Git 基礎：程式碼的「追蹤修訂」

用過 Word 的「追蹤修訂」，你就懂 Git 在做什麼了。

Git＝程式碼的追蹤修訂。

寫一份企劃，每隔一段時間就「另存新檔」：企劃 v1、企劃 v2、企劃 v3。改壞了，還能回到之前的版本。

Git 做的就是這件事，而且比「另存新檔」多做了三件：
- 記下每一次改了哪幾行，不用存一整份副本
- 讓好幾個人同時改同一個專案
- 把紀錄放到雲端（GitHub）備份

Git 和 GitHub 差在哪：Git 是裝在你電腦上、負責記紀錄的工具；GitHub 是放這些紀錄的網站，像雲端硬碟，另外多了討論、審核修改、找別人做好的專案這些功能。Git 不用 GitHub 也能用，只是紀錄只存在你自己的電腦上。

核心概念對照表

Git 術語 白話意思 生活比喻
commit 存一個紀錄點 遊戲的存檔點，隨時可以回到這裡
push 上傳到雲端 把存檔上傳到 GitHub 備份
pull 從雲端下載 把別人的最新存檔下載下來
branch 分支，一個平行宇宙 開一條平行的路改東西，不影響主線，可以放心實驗
merge 合併 平行宇宙裡實驗成功了，併回主線
clone 複製整個專案 把別人的專案整份抓到你的電腦上
staging 準備區 要存檔的東西先放進「待存清單」

常用的 5 個 Git 指令

# 1. 看現在的狀態（哪些檔案被改了？）
git status

# 2. 把改過的檔案放進「待存清單」
git add .　　　　　# 全部放進去
git add index.html　# 只放指定的檔案

# 3. 存檔（建立一個紀錄點）
git commit -m "修好報價單的計算按鈕"

# 4. 上傳到 GitHub
git push

# 5. 下載別人的最新修改
git pull

Branch：開一條平行的路

Branch 的運作方式 main（主線）： A ── B ── C ── D ── E（穩定版本） \ / feature/login： X ── Y ──（試新功能） 在 C 的時候，開了一個新分支叫 feature/login 在分支上改了 X 和 Y 兩次 測試沒問題，在 E 的位置併回 main 試失敗了？刪掉分支，main 完全不受影響

改壞了，怎麼回到上一個存檔點

這是 Git 真正值錢的地方，也是為什麼要常 commit。回去有兩種做法，差很多：

做法 做了什麼 什麼時候用
git revert 新增一筆紀錄，把某次修改「反著做一遍」。舊紀錄都還在 已經 push 上去、別人可能拉過了。大部分情況用這個
git reset --hard 整個退回某個存檔點，之後的修改和還沒存檔的東西直接丟掉 只在自己電腦上、確定後面的都不要了才用。丟掉的找不太回來

Claude Code 自己也有倒回的功能（/rewind，第十章有講），可以把它剛剛改的檔案退回去，但只限它用內建編輯功能改過的檔案。改動大、跨很多次對話的，還是靠 Git 的存檔點。

這些指令不用你自己打
大部分時候，Git 的操作 Claude Code 會幫你做。你要懂的是概念，這樣它說「我開了一個 branch」「要不要 commit 這些修改」的時候，你知道它在做什麼，也知道什麼時候該說「先 commit 一次再改」：改壞了，才有地方回去。

還有一條邊界：它要用 reset --hard、push --force 這類會把紀錄丟掉或蓋掉的指令時，先叫它停下來講清楚會丟掉什麼。

Claude 常提的套件：先認臉

「套件」（package）是別人寫好的工具，拿來就能用，不用自己從頭寫。像蓋房子不用自己燒磚，去建材行買就好。

Claude 很愛順手加套件。下面這張表給你認臉用，第三欄是放在本書這套組合（純靜態頁面放 Cloudflare、資料放 Supabase 或 D1）裡怎麼看：

套件 做什麼 在本書的組合裡
React、Vue 把網頁拆成一塊一塊的元件，重複使用，像蓋積木 要打包。做網站不從這裡開始（第十一章）
Next.js React 加上換頁、伺服器那一半 要打包。手上已經有 Next.js 專案才會碰到，新專案不從這裡開始
Tailwind CSS 不用另外寫 CSS 檔，直接在 HTML 上寫 class 就有樣式，像預製傢俱 正式上線的用法要打包；官方免打包的版本（Play CDN）寫明只給開發試用
Express 用 JavaScript 寫後端 要一台一直開著的機器。先看 Cloudflare Workers 或 Supabase Edge Functions 夠不夠（第七章）
Prisma 用程式操作資料庫，少寫 SQL，像資料庫翻譯機 用 Supabase 的話通常用不到，它直接給你讀寫資料的 API
Zod 檢查收到的資料格式對不對，像品管員 可以用。但檢查一定要在後端做一次，頁面上的檢查只是方便填表的人（第十六章）
i18next、next-intl 讓網站支援中文、英文、日文等多國語言 要做多語言才需要。next-intl 是給 Next.js 用的。要不要做，一開始就決定（見下面的框）
Stripe 讓網站能收信用卡，不用自己處理刷卡的流程 金額一定在後端算，不能信頁面上傳來的數字（第十六章）
Resend、Nodemailer 程式自動寄信（驗證信、通知信、電子報） 寄信用的金鑰放後端，不放頁面上。Nodemailer 要在 Node.js 的後端上跑；本書的組合先看 Resend 這種用 API 寄信的服務
Sharp 壓縮、裁切、轉檔圖片，讓網站載入更快 要在 Node.js 上跑，瀏覽器裡不能用。純靜態網站的話，請 Claude 在你電腦上用它把圖片先壓好再上傳就好
多語言：一開始就要決定
i18n 是 internationalization（國際化）的縮寫，i 和 n 中間有 18 個字母，意思是讓網站支援多國語言。

要做的話，一開始就把畫面上的文字集中放在翻譯檔，不要寫死在每一頁裡。之後要加新語言，多一份翻譯檔就好。等做了幾十頁才要加英文版，就得把每一頁的文字一個一個抽出來，工程很大。確定不做，也講清楚，Claude 就不會自作主張先裝。
不用背，要會問
這張表不用記，是給你「認臉」用的。Claude 說「我用 Prisma 幫你寫查詢」「要不要加 Zod 做檢查」的時候，你至少知道它在說什麼。

它說要裝一個新套件時，問它三句：「這個要不要打包？」「要不要一台一直開著的機器？」「不裝的話，有沒有更簡單的做法？」三句都答得出來，你就知道這個套件會不會把東西越弄越重。

反過來，你想做一個功能、不知道該用什麼，就直接問：「我想做線上預約，有沒有現成的套件或專案？先上 GitHub 找，找到能用的就不要從零做。」

這頁帶走什麼

  • 錯誤訊息找三樣：類型、原因、位置。看不懂就整段貼給 Claude，加一句你剛剛做了什麼。修錯時不准它把錯誤藏起來、把檢查拿掉。
  • 金鑰放 .env，不進 Git；上線放平台的 secret。頁面上只能放 publishable key。外流了先作廢、換新的。
  • Git 是存檔點。改大東西之前先 commit 一次，改壞了才回得去；回去優先用 revert。
  • Claude 要加套件時，先問它要不要打包、要不要一台一直開著的機器。
跟 Claude 怎麼說
「這是主控台的錯誤訊息，我是按下計算之後出現的。先告訴我錯在哪個檔案、為什麼、要改哪幾個檔，我說好再改。不要用把錯誤藏起來的方式修。」
「檢查這個專案有沒有金鑰寫死在程式裡，或是出現在頁面的 JS 裡。有的話列給我看，移到後端的 secret。」
「改之前先 commit 一次，訊息寫清楚這次要改什麼。」
「剛剛那次修改不要了，用 revert 退回去，不要用 reset --hard。」
「你要加的這個套件，要不要打包？不裝的話有沒有別的做法？」
