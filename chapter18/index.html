第十八章

其他工具：做影片、管筆記

第十七章看的是邊界沒守住時，東西會怎麼壞。正文最後這一章換到兩件你自己每天會碰到的事：做影片、管筆記。知道有哪些現成的工具可以用，常常比自己從零開始省事得多；這一章分享我實際在用的工具，以及為什麼選它們。挑工具也是在畫邊界：這件事能不能整件交給 Claude Code，做出來的東西以後要不要一直維護。

挑工具，先看兩件事

這一章的兩個工具，是用同一把尺挑的：

  • Claude Code 能不能從頭做到尾。有指令可以打、檔案是純文字，它就能自己開、自己改、自己存。要你用滑鼠一格一格點的軟體，它幫不上多少。
  • 做出來的東西，以後要不要一直維護。網站上線後要一直改，所以第十一章 技術棧選不打包的做法。一支影片交出去就結束了，標準就不一樣。

這兩條就是工具的邊界：哪些整件丟給它，哪些留在你手上。

在找 MCP、懶人包、部署工具？
這些前面講過了：MCP（讓 Claude Code 接上外部服務的連接器）和 Quickstart 懶人包在第十章 Claude Code 怎麼用；Cloudflare、Supabase、Vercel、Render 這些部署工具怎麼選，在第七章 部署。這一章只講前面還沒講過的。

Remotion：用指令做影片

它是什麼

Remotion 是一個用程式做影片的工具。一般做影片，是打開剪輯軟體，用滑鼠把素材一段一段拖到時間軸上。Remotion 反過來：畫面是用 React（做網頁常用的一套寫法）寫出來的，寫好之後下一行指令，它就把畫面一格一格算出來，存成 mp4。

聽起來是工程師的東西。重點在這裡：寫程式的是 Claude，不是你。你負責講這支片要給誰看、要講什麼，剩下的它用指令做完，你不用開剪輯軟體。

比喻：親手彈琴 vs 寫樂譜給自動鋼琴。

剪輯軟體像親手彈琴，每一個音都要你自己按。

Remotion 像寫樂譜交給自動鋼琴。譜（程式）寫好，它照著彈一遍、錄下來，就是影片。想改，就改譜上那一個音，再彈一遍。同一份譜換一段歌詞，還能錄出很多個版本。
示意
一支影片是這樣做出來的：
<標題 文字="新品上市" />
<數字 從=0 到=128 />
1　程式
Claude 把畫面寫成文字檔
→
新品上市 128 萬
2　畫面
Remotion 一格一格算出來
→
影片.mp4
3　影片檔
存成 mp4，直接拿去用

為什麼選它

關鍵在這裡：整支影片就是一堆文字檔，所以 Claude Code 可以從頭做到尾。

  • 全程用指令：開專案、預覽、輸出都是終端機指令，Claude Code 自己會打。第十章講過，有 CLI 的事它做起來順手，做影片也一樣
  • 用講的就能改：「標題再大一點」「整支改成直式」「第二幕縮短成三秒」，改完重新輸出一次就好
  • 同一支片可以換資料重做：版型做一次，換品名、價格、照片，就能一次輸出很多支
  • 有給 AI 看的說明書：Remotion 自己出了一組 Agent Skills，給 Claude Code 這類工具照著官方建議的寫法做
前面不是說不打包？
對。Remotion 的畫面是用 React 寫的，輸出前也要先打包，看起來跟第十一章打架。

差在做出來的東西。網站上線後還要一直改，每改一次就要再打包一次，用到的套件也得跟著升級，所以做網站我不推薦。影片打包完輸出的是一個 mp4 檔，交出去就結束了，不是要長期維護的網站。

而且做影片這件事，它是能全程用指令完成的選擇。所以線畫在這裡：網站不打包，影片可以。

適合什麼、不適合什麼

適合
- 產品介紹短片（用產品照、畫面截圖、文字組成）
- 數字動畫（營業額、成長率跑起來）
- 字卡、片頭片尾
- 同一支片換資料批次產出（每個產品一支、每位客戶一支）
不適合
- 實拍素材要精剪（訪談、活動紀錄）
- 複雜的調色

這些還是交給剪輯軟體。可以分工：實拍的部分在剪輯軟體剪，字卡和數字動畫用 Remotion 做好，再放進去。

做一支片的流程

Remotion + Claude Code 協作流程

你想好這支片給誰看、要講哪幾件事
　　↓
Claude 寫腳本和分鏡，你確認
　　↓
Claude 開專案，把每一幕寫成程式
　　↓
你在瀏覽器預覽，用講的請它改
　　↓
Claude 輸出成 mp4

你是「導演」，只管要什麼
Claude Code 是「製作團隊」，負責做出來

過程中 Claude 會打下面這幾個指令。你不用背，看得懂它在做什麼就好：

指令 在做什麼
npx create-video@latest --yes --blank my-video 開一個空白的影片專案，放在 my-video 資料夾
npx remotion skills add 在專案裡裝上 Remotion 給 AI 用的那組 Skills
npm run dev 打開預覽畫面（叫 Remotion Studio），在瀏覽器裡看影片現在長怎樣
npx remotion render HelloWorld 輸出影片。HelloWorld 換成那支影片在專案裡的名字；沒特別指定的話輸出 mp4，檔案放在專案的 out 資料夾
開始之前
電腦要先裝好 Node.js。用 Mac 的話，系統要 macOS 15 以上。

影片是在你自己的電腦上算出來的，Remotion 不幫你代算。想丟到雲端算，要另外接你自己的雲端帳號（例如 AWS），剛開始用不到。
兩個省時間的習慣
先定腳本，再做畫面。先講清楚這支片要解決觀眾的什麼問題，腳本確認了再讓 Claude 動手。畫面做到一半才改方向，前面等於白做。

用真的素材。產品照、畫面截圖、logo 先放進專案資料夾給它用。讓它憑空「畫」一個你的產品，通常不像。

影片專案也有邊界

影片專案要打包、要裝一堆套件，跟你那個不打包的網站是兩回事。兩邊分開放：

  • 影片專案自己一個資料夾。不要讓 Claude 為了做一支宣傳片，把 Remotion 裝進網站的資料夾。網站一旦多了打包步驟，以後每次改字都要先打包。
  • 網站要放影片，放的是輸出好的 mp4。網站那邊只拿成品，不拿程式。
  • 素材共用，就複製一份過去。logo、產品照從網站資料夾複製到影片專案，不要讓兩個專案互相讀對方的檔案。

授權：先看公司有幾個人

不是所有人都免費
Remotion 收不收錢，看公司人數。以下是 2026 年 11 月官網的說法：

免費：個人，或是總人數 3 人以下的公司、團隊。可以商用，功能跟付費的一樣，不用註冊帳號。還在評估適不適合、還沒正式商用的階段也免費，決定正式用才買。非營利組織原則上免費；政府機關、學校要先取得 Remotion 的書面同意。

要付費：4 人以上的公司要買 Company License。算的是公司總人數，不是「有幾個人在用」。20 人的公司只有 1 個人用，一樣要買。找外面的工作室或接案者一起操作同一個專案，他們的人數也要合起來算。
- 像這一節這樣，自己用 Claude Code 做少量影片（Remotion for Creators）：每位使用者每月 25 美元
- 寫程式讓它自動連續出片，包含換資料批次輸出（Remotion for Automators）：每輸出一次 0.01 美元，每月最低 100 美元

幫客戶做片：只交成品 mp4 給客戶，只算你自己公司的人數。連專案程式一起交給客戶、由客戶自己操作的話，兩家公司的人數要合起來算。

價格和條款會調整，動手前看一次官網：remotion.dev/docs/license/pricing

Obsidian：筆記放在自己的電腦裡

它是什麼

Obsidian 是一個寫筆記的軟體，筆記存成 Markdown（.md）純文字檔。Markdown 是一種「用純文字寫格式」的方法，像是用 # 代表標題、用 - 代表清單項目。你現在看的這個網站，每一頁的內容其實也都可以用 Markdown 來寫。

Obsidian 個人用、公司用都免費，不用註冊。跨裝置同步（Sync）、把筆記發佈成網頁（Publish）是另外付費的加購，不買也能用。

為什麼選它

第一個理由：你的筆記永遠是你的。

很多筆記軟體（像 Notion、Evernote 這類）把資料放在它們的伺服器上。哪天改方案、漲價，或是你想換一套，要搬家得先匯出，格式也不一定能完整帶走。

Obsidian 的筆記就是你電腦裡一個資料夾（它叫 vault，保險庫）裡的 .md 檔。就算哪天不用 Obsidian 了，用任何文字編輯器都打得開。

你的資料不被任何一套軟體綁住。

第二個理由：Claude Code 可以直接讀寫你的筆記。筆記就是電腦裡的檔案，Claude Code 本來就有讀檔、寫檔的工具（Read、Write），不用另外裝東西。它改了檔案，Obsidian 那邊會自動更新。這代表：

  • 你跟 Claude 討論出來的想法、結論，可以直接請它存成一篇筆記
  • 開新對話時，它可以先讀之前的筆記，接上專案的來龍去脈
  • 任務、專案規劃、參考資料，都放在同一個地方

怎麼讓它讀得到：在筆記資料夾裡打開 Claude Code；或是在別的專案裡打 /add-dir，把筆記資料夾加進來。

　　↓

　　↓

Claude Code 是你的「手腳」
建議的資料夾結構

SOP/：反覆執行的流程

筆記資料夾的最上層，也可以放一份 CLAUDE.md，寫這個資料夾的規矩：每個資料夾放什麼、新筆記放哪裡、哪些不准動。Claude 每次在這裡開工都會先讀它，跟第三章講的邊界文件是同一件事。

筆記也有邊界

筆記一多，也會出現第十七章 會出事的地方講的問題。三條規矩先講好：

  • 一件事只寫在一篇。同一個報價寫在三篇筆記，改了一篇，另外兩篇就是錯的。其他地方要提到，用 [[篇名]] 連過去就好。這就是單一資料來源，筆記也適用。
  • 金鑰、密碼、客戶個資不寫進筆記。Claude 讀得到的東西，就可能被它引用到對話或別的檔案裡。
  • 讓它改筆記之前，先說好範圍。例如「只能動 Inbox 和這個專案的資料夾」。不講，它整理起來可能順手把別的筆記也改了。

怕它改壞？筆記資料夾也可以用 Git 存檔，改壞了回到上一個存檔點，做法見附錄 Git 基礎。要備份到 GitHub 的話，用私人的 repo。

其他常用工具

下面這幾個，是前面幾章那套組合（純靜態頁面放 Cloudflare、資料放 Supabase 或 D1、版控用 GitHub）會一起用到的。大部分是 CLI，Claude 自己會打，你知道它是做什麼的就好：

工具 一句話
Git 替檔案留下每一次修改的紀錄，改壞了能回到前一版。基本概念見附錄 常見問題
gh GitHub 的官方 CLI。開 repo、開 PR、用 gh search repos 找有沒有現成的，都不用你去點網頁
wrangler Cloudflare 的官方 CLI。部署網站、建 D1 資料庫、存金鑰都靠它
supabase Supabase 的官方 CLI。記下資料表的每一次變更（migration），部署後端小程式（Edge Functions）
Node.js 很多工具要它才跑得動，Remotion 也是。Claude 常打的 npx 就是它附的，意思是「抓這個工具來跑一次」
Claude in Chrome 讓 Claude 在你的 Chrome 裡開網頁、點按鈕、填表單、看主控台的錯誤。沒有 CLI 的網頁工作交給它

用哪個工具，順序跟第十章 Claude Code 怎麼用一樣：有官方 CLI 的先用 CLI；沒有才裝 MCP（連接器）；操作網頁交給瀏覽器工具；都不行才用 Computer Use。就算一個 MCP 都沒裝，Claude Code 本來就能讀寫檔案、跑指令、上網查資料。

這章帶走什麼

  • 挑工具看兩件事：Claude Code 能不能從頭做到尾，做出來的東西要不要長期維護。
  • Remotion 要打包，但輸出的是影片檔，交出去就結束。網站不打包，影片可以；影片專案跟網站分開放。
  • Remotion 4 人以上的公司要付費，算的是公司總人數。動手前看一次官網。
  • Obsidian 的筆記是你電腦裡的純文字檔，Claude Code 直接讀寫，不用另外接。
  • 筆記也守單一資料來源：一件事只寫一篇，其他地方用連結。改之前先說好範圍。
跟 Claude 怎麼說
做影片
「我要做一支 30 秒的產品介紹短片，直式 1080×1920。先不要寫程式，先幫我寫腳本和分鏡，我確認後再用 Remotion 做。素材放在『素材』資料夾，有三張產品照和一張 logo。」
「第二幕的營業額，數字從 0 跑到 128 萬，跑 2 秒，停一下再進下一幕。改好後開預覽給我看。」
「同一支片，照『產品清單』這個檔案，每一列換品名、價格、照片，各輸出一支 mp4，檔名用品名。」
「影片專案開在另一個資料夾，不要裝進網站的資料夾。做好只把 mp4 複製到網站的 videos 資料夾。」

管筆記
「把今天討論的結論整理成一篇筆記，放進專案資料夾。已經有寫過的事，用連結指過去，不要再抄一份。」
「這次只能動 Inbox 和『B 咖啡店官網』這個資料夾，其他筆記不要改。」

選工具
「這件事有官方 CLI 的話用 CLI 做，沒有再用 MCP。」
