第八章

網域：買一個網址，接到你的網站

第七章把 B 咖啡店的預約頁面放上網了，但網址又長又難記。這章帶你買一個自己的網址，把它接到那個頁面，順便把小鎖頭、子網域、收信這幾件事一次講清楚。

上一章做完，B 咖啡店的「線上預約表」已經在網路上了，任何人打開網址都看得到。問題是那個網址長得像 b-cafe-booking.某某某.workers.dev，老闆印不上名片，客人也記不住。

這一章要做的事只有一件：讓客人打 book.b-cafe.example 這種短短的、看得出是誰家的網址，就到得了同一個預約頁面。為了做到這件事，會順便碰到幾個你一定聽過、但可能從沒搞懂的東西：網域、DNS、HTTPS 小鎖頭、MX 紀錄。不用背，照著做一遍就有感覺了。

書裡的網址是假的

這章用 b-cafe.example 當 B 咖啡店的網址。.example 這個結尾是國際上保留給「寫範例用」的，任何人都買不到，所以不會不小心指到別人的網站。你實際操作時，換成你自己買的網址就好。

網域是什麼：門牌，不是房子

第五章講過：網域（Domain）是網站的門牌。你不用記大樓的座標（IP 位址），記門牌就好。這裡不重講，只補一個買網址之前一定要懂的觀念：

門牌和房子是分開買的。第七章你已經「租了房子」：頁面放在 Cloudflare 上。這章是去「申請門牌」，再把門牌釘到那間房子上。門牌可以換房子掛（以後網站搬家，門牌不用換），房子也可以同時掛好幾塊門牌。

所以「買網域」不等於「做網站」。只買網域，什麼都不會出現；只有房子沒門牌，網站照樣能用，只是地址很醜。兩件事接起來，才是客人看到的樣子。

還有一件事要先知道：網域不是買斷，是按年租。一次可以先付一年或好幾年，到期要續約。忘了續約，門牌會被收回，之後可能被別人買走。這件事後面會一再提到，因為它是這整章最容易出大事的地方。

.com、.com.tw、.tw：結尾怎麼選

網址最後面那段叫頂級網域（TLD）。它決定了兩件事：你能不能買、去哪裡買。

結尾 誰可以買 大家看到的感覺
.com 任何人 最常見，全世界通用。好名字很多已經被買走
.com.tw 依法設立登記的公司、行號、有限合夥、其他營利團體，或完成稅籍登記的執業專業人士 一看就是台灣的公司。個人工作室還沒登記的不能買
.tw 個人、公司都可以。跟 .com.tw 不同，不用公司登記（實際條件以你選的註冊商頁面為準） 短、看得出是台灣
.idv.tw 個人，任何自然人都可以申請 個人網站、作品集
.org.tw 財團法人、非營利社團法人等非營利組織 協會、基金會
.台灣 TWNIC 管理的中文結尾，前面可以是中文或英文 好記，但有些系統、表單不支援中文網址，用之前先試

.tw 系列都由台灣網路資訊中心（TWNIC）管理，上面的資格照 TWNIC 官網和註冊商頁面整理（2026-11-13 查）。整理成一句話：有公司登記，可以考慮 .com.tw；還沒登記、或想要國際通用，選 .com。

B 咖啡店有商業登記，所以 .com.tw 和 .com 都能買。很多店家兩個都買，一個主用，另一個轉過去，免得被別人搶註。要不要兩個都買是預算問題，不是技術問題。

名字怎麼取

  • 念得出來、拼得出來：電話裡講一次對方就打得對。避免 0 和 o、l 和 1 這種容易看錯的組合
  • 短：要印在名片、杯套、招牌上
  • 不要跟大品牌撞名：撞到別人的商標，之後可能被要求交出來
  • 先想好用途分層：主網址給品牌，功能放子網域。預約放 book.、訂購放 shop.，這個後面會講

去哪裡買

賣網域的店叫註冊商（Registrar）。同一個網址在哪一家買都一樣，差在價錢、介面、能買哪些結尾、DNS 好不好管。這裡只講兩條路，都是查得到官方頁面的。

路線 A：Cloudflare Registrar

第七章頁面已經放在 Cloudflare，網域也在同一家買，接起來最省事。官方文件寫的幾個重點：

  • 照成本價賣：官方寫照註冊局的價格收，不另外加價，續約也照註冊局的牌價。實際價錢要在 Cloudflare 的購買頁面看（以官方頁面為準，2026-11-13 查）
  • 預設開自動續約，隨時可以關
  • 聯絡資料預設遮起來：註冊局允許的話，你的個人資料不會被公開查到
  • DNS 一定要用 Cloudflare 的：在這裡買的網域，不能改用別家的 DNS

限制也要知道：

  • 不賣 .tw、.com.tw（Cloudflare 支援清單上沒有，2026-11-13 查）。要台灣結尾只能走路線 B
  • 不支援中文網址：有特殊字元的國際化網域名稱買不到
  • 聯絡資料只收英文字母：公司名、地址要用英文或拼音填，而且要完整正確，資料不實可能被停用或取消

路線 B：台灣的註冊商

TWNIC 官網有一份「受理註冊機構」名單，名單上的才能賣 .tw 系列。台灣人常見的像是中華電信 HiNet 的網域註冊、PChome 的買網址，名單上還有十幾家，可以自己去看。

  • 好處：中文介面，能買 .com.tw、.tw、.台灣，公司名可以照中文登記
  • 要注意：各家價錢、首年優惠、續約價都不一樣，DNS 管理畫面也各長各的。之後要接 Cloudflare，得到註冊商那邊改一個叫「名稱伺服器」的設定（下面步驟會帶）

PChome 買網址的頁面寫明：從 2023 年 6 月 1 日起，.tw 網域在公開查詢上預設不顯示聯絡資料。也就是 .tw 系列不用另外加買隱私保護。

兩條路怎麼選

要 .com：Cloudflare 買，最少步驟。要 .com.tw：台灣註冊商買，再把 DNS 交給 Cloudflare 管。兩條路最後都會變成「DNS 在 Cloudflare」，後面的步驟就一樣了。

買的時候要注意的事

網域很便宜，但出事的時候很貴。下面每一條，都是有人真的踩過的。

1. 看續約價，不是只看首年價

有些註冊商首年很便宜，第二年起恢復原價。比價時把「續約價」那一欄找出來，算三年總共多少。Cloudflare 官方說續約照註冊局牌價；其他家請在購買前看清楚價格說明頁。

2. 自動續約要開，信用卡要有效

自動續約開著，卡過期一樣扣不到款。網域到期前註冊商會寄信提醒，那封信寄到哪個信箱很重要：要寄到一個你真的會看的信箱，不要用已經離職員工的信箱。

B 咖啡店的做法：用店裡共用的信箱註冊，並在行事曆上自己再設一個到期前一個月的提醒。

3. 隱私保護

網域的註冊資料以前是公開查得到的，現在多數會遮起來。Cloudflare 預設遮；.tw 系列從 2023 年 6 月起預設不顯示。在其他家買 .com，結帳時看一下有沒有「隱私保護」或類似選項，是不是要另外付錢。

4. 帳號用誰的名字

網域登記在誰名下，法律上就是誰的。公司的網址，就登記公司；用公司的信箱開帳號。不要登記在老闆個人、員工個人名下，以後拆夥、離職、繼承都會很麻煩。

5. 不要讓外包用他的帳號幫你買

這條最常出事

外包說「網址我幫你買就好，比較快」。快是快，但網域就在他的帳號裡。哪天合作不愉快、他聯絡不到、或公司收掉，你的網址可能就拿不回來，名片、招牌、Google 上的評價全部指向一個你管不了的地方。

正確做法：你自己開帳號、自己付款、網域在你名下。需要外包幫忙設定，就把他加成你帳號底下的成員，或你在旁邊登入讓他操作，做完收回權限。

已經在別人帳號裡的網域，可以轉到你自己的帳號或別家註冊商，但要對方配合。國際網域管理機構 ICANN 的說明是：剛註冊、剛轉移、或剛改過註冊人名字的 60 天內，註冊商可以拒絕轉出。越早處理越好。

DNS 是什麼：網路的電話簿

DNS 是一本電話簿。你要打給「B 咖啡店」，不用背電話號碼，翻電話簿查名字就找到號碼。瀏覽器也一樣：你打 book.b-cafe.example，它先去 DNS 查「這個名字對到哪台機器」，查到了才連過去。

買了網域，等於在電話簿裡有了一頁屬於你的格子。格子裡要寫什麼，由你決定，一行叫一筆紀錄（record）。你不用會寫，但要看得懂這幾種：

種類 一句白話 B 咖啡店的例子
A 這個名字對到哪個 IP 位址（機器的號碼）。另一種 AAAA 是新版號碼 用 Cloudflare 的話通常不用你填，它會自己處理
CNAME 這個名字是另一個名字的別名：「查我，請去查它」 order.b-cafe.example → 外部訂購平台給你的網址。接第七章的 Worker 不用自己加 CNAME，步驟 3 交給 Cloudflare 自動建；先手動加了，步驟 3 反而會失敗
MX 寄到這個網域的信，要送到哪個郵件伺服器 寄給 hello@b-cafe.example 的信送去店裡用的信箱服務
TXT 一段文字，通常是給別的服務驗證「這個網域真的是你的」 開 Google 商家、信箱服務時，對方要你貼一段驗證碼

還有一個詞會出現：名稱伺服器（nameserver）。它是「這本電話簿放在誰家」。網域在台灣註冊商買、電話簿要交給 Cloudflare 管，就是去註冊商那邊把名稱伺服器改成 Cloudflare 給你的那兩個。改完之後，所有紀錄都在 Cloudflare 的畫面裡管。

客人打網址的那一刻，發生了什麼

  1. 客人的手機打 book.b-cafe.example瀏覽器還不知道要去哪
  2. 查 DNS翻電話簿「book 這行寫的是：去 Cloudflare」
  3. Cloudflare出示憑證手機確認身分沒錯，網址列出現小鎖頭
  4. 預約頁面送到手機就是第七章放上去的那份檔案

頁面本身是第七章從你的電腦、經過 GitHub 放上 Cloudflare 的。這章只是在電話簿裡多寫一行，讓好記的名字也找得到它。

DNS 改了不會馬上全世界生效。電話簿有很多份副本散在各地，每份都要時間更新。Cloudflare 自己的紀錄通常幾分鐘內就好；改名稱伺服器這種大動作，官方說最多可能要等 24 小時。改完沒看到效果，先等，不要一直改。一直改只會讓你搞不清楚現在是哪一版。

動手做：把 B 咖啡店的網址接上預約頁

目標：客人打 book.b-cafe.example，看到第七章那個預約頁面，網址列有小鎖頭。

每一步分成三格：要做什麼、跟 Claude 怎麼說、你自己要動手的地方。第三格是註冊帳號、登入、付款、收驗證信、按允許這類事，Claude 不該也不能替你做。下面寫的按鈕名稱，是 2026-11-13 照 Cloudflare 官方文件寫的；畫面改版的話，跟 Claude 說「照官方文件現在的做法帶我」就好。

步驟 1

想名字、查有沒有被買走

要做什麼

列出三到五個候選名字，確認哪些還能買、該選哪個結尾。

跟 Claude 怎麼說

「我是 B 咖啡店，有商業登記。幫我想五個好念、好拼的網址候選，各給 .com 和 .com.tw 兩種。用 whois 查哪些看起來還沒被註冊，列成表。只查，不要幫我買任何東西。」

你自己動手

從表裡挑一個，念給一個朋友聽，請他打出來，看拼不拼得對。

做完會看到

一張表：名字、結尾、看起來能不能買。Claude 查的只是參考，最後以註冊商搜尋結果為準。

常見卡住
  • 喜歡的名字都被買了：加地名或品類，例如 b-cafe-taichung、bcafe-coffee。不要用一長串數字
  • whois 查不到結果：有些結尾不開放這樣查，直接到註冊商的搜尋框打打看
步驟 2

買網域（路線 A：.com 在 Cloudflare 買）

要做什麼

在 Cloudflare 上把網址買下來。要 .com.tw 的人跳到步驟 2B。

跟 Claude 怎麼說

「我要在 Cloudflare Registrar 買 b-cafe.example。照官方文件現在的步驟，一步一步告訴我要點哪裡、每一格填什麼。付款和送出我自己按。」

你自己動手
  • 用第七章那個 Cloudflare 帳號登入，不要另外註冊新帳號。確認登入的是同一個帳號、信箱已經驗證過（沒驗證過的帳號買不了網域）
  • 網域一定要買在放預約頁的同一個帳號裡。分在兩個帳號，步驟 3 會找不到這個網域，接不起來
  • 到 Register domains 頁面，搜尋框打名字，按 Search
  • 在要的網址旁按 Purchase，在 Payment option 選要先付幾年
  • 填聯絡資料（只能填英文字母，公司名用英文或拼音）
  • 選付款方式、看過條款，按 Complete purchase
做完會看到

官方說註冊最多約 30 秒完成。網域會出現在你的帳號裡，畫面上有一個下次自動續約的日期。信箱會收到一封要你驗證註冊人信箱的信。

常見卡住
  • 沒收驗證信、或放著不理：ICANN 規定註冊人信箱要驗證。沒驗證，網域會被暫停、指到停放頁面，網站打不開。去垃圾信匣找，點完連結
  • 聯絡資料打中文被擋：這裡只收英文字母，改用英文或拼音
  • 搜尋結果沒有你要的網址：代表已經被買走，或 Cloudflare 不賣這個結尾
步驟 2B

買網域（路線 B：.com.tw 在台灣註冊商買），再把 DNS 交給 Cloudflare

要做什麼

在台灣註冊商買好網址，把它加進 Cloudflare，最後到註冊商那邊把名稱伺服器改成 Cloudflare 給的兩個。

跟 Claude 怎麼說

「我在台灣的註冊商買了 b-cafe.example，要把 DNS 改給 Cloudflare 管。照 Cloudflare 官方文件現在的步驟帶我。改名稱伺服器之前，先幫我列出這個網域現在所有的 DNS 紀錄，特別是 MX 和 TXT，存成一個檔案給我留底。」

「我改完名稱伺服器了，幫我查生效了沒。」

你自己動手
  • 在註冊商開帳號、付款買網域（公司登記資料照實填，.com.tw 會審資格）
  • 用第七章那個 Cloudflare 帳號登入（放預約頁的同一個帳號），到 Domains，按 Onboard a domain，輸入網址，選免費方案
  • Cloudflare 會掃描現有紀錄。拿 Claude 列的留底檔逐行對，少的自己補上
  • Cloudflare 會給你兩個名稱伺服器。登入註冊商的管理頁，把原本的名稱伺服器換成這兩個，一字不差
做完會看到

Cloudflare 的 Domains 頁面上，這個網址的狀態變成 Active，並且會收到 Cloudflare 寄來的通知信。在那之前會先停在等名稱伺服器更新的狀態。

常見卡住
  • 等了很久還沒 Active：官方說最多可能要 24 小時。超過了，請 Claude 查名稱伺服器是不是拼錯一個字
  • 註冊商那邊有開 DNSSEC（一種防偽造的簽章設定）：官方提醒要先關掉再改名稱伺服器，不然網站可能整個連不到。換好之後可以在 Cloudflare 重新開
  • 掃描漏了紀錄：官方說掃描不保證抓得到全部。漏掉的多半是 MX，後果是收不到信，見後面「拿網域收信」
步驟 3

把 book 子網域接到第七章的頁面

要做什麼

告訴 Cloudflare：book.b-cafe.example 這塊門牌，掛到第七章那個預約頁面。

第七章的頁面可能是用 Cloudflare 的 Workers 放的，也可能是 Pages。兩邊做法不同，讓 Claude 先看你的專案是哪一種。

跟 Claude 怎麼說

「把 book.b-cafe.example 接到第七章部署的預約頁面。先看這個專案是 Workers 還是 Pages，照 Cloudflare 官方文件現在的做法設定自訂網域。設定前先告訴你打算改哪個檔案、加哪一筆 DNS 紀錄，等我說好再動。不要動到其他 DNS 紀錄。」

你自己動手
  • Claude 第一次用 wrangler（Cloudflare 的 CLI）時要登入：它會開一個瀏覽器頁面，由你確認是自己的帳號、按同意授權
  • 看 Claude 列的改動計畫，確認只動 book 這一筆，回它「好」
做完會看到

Workers 的話：設定檔裡多了幾行（下面有樣子），部署之後，Worker 的 Settings → Domains & Routes 裡會列出 book.b-cafe.example。Cloudflare 會自己幫你建好 DNS 紀錄和憑證。

Pages 的話：在 Workers & Pages 選這個專案 → Custom domains → Set up a domain，輸入網址按 Continue。網域已經在 Cloudflare 的，它會自動加好 CNAME 紀錄。

常見卡住
  • Workers 加不上，說名字已被占用：官方寫明，已經有 CNAME 紀錄的名字不能再設成自訂網域。多半是之前自己手動加過一筆，請 Claude 列出來、跟你確認後再處理
  • Pages 打開出現 522 錯誤：官方說沒先在 Pages 的 Custom domains 綁定，就直接去 DNS 加 CNAME，會出現這個錯。回到上面那個畫面補綁定
  • Workers 要求網域在 Cloudflare 上：還沒做步驟 2 或 2B 的，先回去做。做了還是找不到網域，多半是網域和預約頁分在兩個 Cloudflare 帳號，請 Claude 幫你確認

Workers 的做法，Claude 會在設定檔 wrangler.jsonc 加上這一段（官方文件的寫法，網址換成你的）：

{ "routes": [ { "pattern": "book.b-cafe.example", "custom_domain": true } ] }

你不用會寫，但看得懂就好：pattern 是門牌，custom_domain: true 是「這是一個自訂網域」。改完它會用 wrangler 重新部署。以後網站搬家、門牌要換，就是改這幾行。

步驟 4

驗收：打得開、有小鎖頭、舊網址還在

要做什麼

確認客人真的打得開，而且是安全連線。

跟 Claude 怎麼說

「幫我驗收 book.b-cafe.example：查 DNS 有沒有生效、https 打不打得開、憑證是不是有效的、打開的內容是不是第七章那個預約頁。用 http 開會不會自動跳到 https。結果列成清單，有問題先不要改，跟我說原因。」

你自己動手
  • 用自己的手機、關掉 Wi-Fi 改用行動網路打開一次
  • 點一下網址列的小鎖頭，看憑證是不是發給這個網址
  • 試填一次預約表（第九章之前，資料還不會真的存起來）
做完會看到

手機打得開預約頁，網址列有小鎖頭、沒有「不安全」字樣。Claude 回報的清單每一項都通過。

常見卡住
  • 電腦打得開、手機打不開（或相反）：通常是 DNS 副本還沒全部更新。等一下再試，不要急著改設定
  • 出現「不安全」或憑證錯誤：憑證要等網域生效後才會發。剛設定完先等；等很久還是這樣，請 Claude 查 DNS 紀錄裡有沒有一筆叫 CAA 的設定擋住了 Cloudflare 發憑證
  • 打開是舊內容：瀏覽器存了舊版。用無痕視窗開一次
步驟 5

把新網址換到客人看得到的地方

要做什麼

名片、Google 商家、社群簡介、LINE 官方帳號上的連結，換成新網址。

跟 Claude 怎麼說

「幫我做一張 book.b-cafe.example 的 QR Code 圖檔，存在 assets 資料夾。再列一張清單：店裡哪些地方可能還放著舊網址，讓我一個一個去換。」

你自己動手

登入各平台改連結。這些是你的帳號，登入跟送出由你來。

做完會看到

用手機掃 QR Code，直接開到預約頁。

常見卡住

舊網址要不要關：先不要。第七章那個長網址留著，萬一新網址出問題，還有一條路。等新網址穩定一陣子再決定。

子網域：一個網址，分好幾個門

第五章說過，子網域是「大樓裡的哪個部門」。買一個 b-cafe.example，前面要加什麼都不用再付錢：

  • b-cafe.example：品牌首頁
  • book.b-cafe.example：線上預約（這章做的）
  • shop.b-cafe.example：以後要賣咖啡豆再開
  • admin.b-cafe.example：店員看預約的後台（第九章之後才會有）

為什麼預約要放子網域，不放 b-cafe.example/book 這種路徑？兩種都可以，差在拆不拆得開：

  • 子網域：每個功能是獨立的一個網站，可以各自放在不同地方、各自部署。預約頁壞了，首頁不受影響。以後預約改用現成的訂位系統，把 book 這一行指過去就好
  • 路徑：全部都在同一個網站裡，管理簡單，但改一個地方要整站重新上傳

這就是第十三章架構拓樸要講的「怎麼切」。小店家的經驗法則：給客人用的、給店員用的分開；會換供應商的東西，給它一個自己的子網域。

www 和沒有 www

www.b-cafe.example 和 b-cafe.example 在電話簿裡是兩行，不會自動相通。Cloudflare 的文件也寫明，自訂網域是一個名字對一個名字。所以要決定一個當正式網址，另一個設定成自動轉過去。

「b-cafe.example 當正式網址。有人打 www.b-cafe.example，自動轉到 b-cafe.example，路徑要跟著帶過去。照 Cloudflare 官方文件現在建議的方式做，先跟我說你要怎麼設。」

HTTPS 小鎖頭怎麼來的

小鎖頭像是店門口掛的營業登記證。客人一進門先看一眼：這間店真的叫這個名字，不是冒牌的。看完之後，店裡講的話也只有你們兩個聽得到。

網址前面的 https 代表加密連線。瀏覽器連上網站時，網站要拿出一張憑證（SSL／TLS 憑證），證明「我就是 book.b-cafe.example」。憑證由公認的發證單位核發，瀏覽器認得，就顯示小鎖頭；不認得，或沒有憑證，就跳「不安全」。

以前憑證要自己買、自己裝、每年記得換。放在 Cloudflare 上就不用：

  • 網域在 Cloudflare 上生效後，官方說會免費自動發憑證，也會自動續期，免費方案就有
  • Workers 加自訂網域時，官方說會替那個名字產生憑證
  • 自動發的憑證涵蓋主網域和「一層」子網域：book.b-cafe.example 沒問題；a.book.b-cafe.example 這種兩層的不在預設範圍，所以子網域不要疊太多層
小鎖頭不等於安全

小鎖頭只保證「連線是加密的、網址沒被冒充」。頁面裡有沒有把不該公開的東西放出來，它不管。例如把資料庫的管理金鑰寫進網頁，加密連線只是把金鑰「安全地」送給每個訪客。這件事第九章和第十六章會講。

網域之後要拿來收信

有了網域，店家常常下一步就是 hello@b-cafe.example 這種信箱。收信靠的是電話簿裡的 MX 紀錄：它告訴全世界「寄給這個網域的信，送到哪個郵件伺服器」。

MX 紀錄最怕的不是不會設，是被不小心蓋掉或刪掉。蓋掉的那一刻什麼都不會壞，網站照樣打得開，只是信開始寄不進來，往往過了好幾天才有人發現「怎麼最近都沒有客人來信」。常見的幾個時機：

  • 把 DNS 搬到 Cloudflare 時：掃描沒抓到原本的 MX，搬完就沒了。這是步驟 2B 要你先留底的原因
  • 設定網站時，工具或教學叫你「先清掉舊紀錄」：清掉的可能包括 MX
  • 換信箱服務時：新舊兩家的 MX 同時留著，或舊的刪了新的還沒加
  • 開了 Cloudflare 的郵件轉寄（Email Routing）：它會加上自己的 MX，把信轉到你指定的信箱。原本已經在用別家信箱的，要想清楚信要送去哪一邊

B 咖啡店的規矩寫成一句，放進專案的 CLAUDE.md（第十章講過，這是給 Claude 的交代）：

「動任何 DNS 紀錄之前，先列出現在所有的紀錄存檔。MX 和 TXT 紀錄一律不准改、不准刪，要動先問我。」

TXT 紀錄也一樣要小心。信箱服務常要你加幾筆 TXT（業界叫 SPF、DKIM、DMARC，作用是證明「這封信真的是從這個網域寄出來的」，少了信容易被丟進垃圾信匣）。看到這幾個字開頭的 TXT，就當成跟 MX 一樣重要。

Cloudflare 上的 MX、TXT 紀錄不能開「代理」（畫面上那朵橘色雲），只有 A、AAAA、CNAME 可以。看到 Claude 想把 MX 改成代理，就是它搞錯了。

哪裡有邊界

這章的每個動作，都可以分成「放心交給 Claude」和「一定要你自己確認」兩堆。分的原則很簡單：查、寫設定、檢查，交給它；花錢、登入、刪東西、會影響別人的，你自己來。

放心交給 Claude

  • 想名字、查有沒有被註冊、比價（附來源網址）
  • 照官方文件一步一步帶你點畫面
  • 改 wrangler.jsonc、重新部署
  • 列出現有 DNS 紀錄、存成留底檔
  • 查 DNS 生效沒、HTTPS 正不正常
  • 做 QR Code、整理要換網址的清單

一定要你自己

  • 開帳號、登入、驗證信箱
  • 付款、設定自動續約、確認信用卡有效
  • 網域登記在誰名下
  • 到註冊商改名稱伺服器
  • 刪除任何 DNS 紀錄，尤其 MX、TXT
  • 網域轉移、讓別人加入你的帳號
  • 授權 wrangler 登入時按同意

還有三件事，這章只點到，後面的判斷章節會細講：

  • 金鑰不能放進頁面：Cloudflare 的 API 金鑰、第九章會拿到的資料庫金鑰，任何一把能改東西的鑰匙，都不能寫進網頁的檔案，也不能推上公開的 GitHub。網頁是會送到每個訪客手上的。什麼能放前面、什麼一定要在後面，見第十六章 前後端邊界
  • 付款與續約：網域到期沒續，不只網站打不開，信也收不到。這類「平常不會壞、一壞就全壞」的地方，見第十七章 會出事的地方
  • 刪除資料庫：下一章會建資料庫。刪掉資料庫跟刪掉 MX 紀錄一樣，按下去當下看不出事，事後救不回來，一律你自己確認

網站要拆成幾塊、每塊放哪裡、子網域怎麼分，是第十三章 架構拓樸和第十四章 功能怎麼切的題目；預約資料要存哪些欄位，是第十五章 資料表與欄位。現在先把門牌掛好，知道這幾條線在哪就夠了。

這章帶走什麼

  • 網域是門牌，網站是房子，兩個分開買、再接起來。網域是按年租的，要續約。
  • 有公司登記可以選 .com.tw；國際通用選 .com。Cloudflare 不賣 .tw 系列，要的話去 TWNIC 名單上的台灣註冊商買。
  • 網域登記在公司名下、用自己的帳號買，不要讓外包用他的帳號代買。看續約價，開自動續約，確認提醒信寄得到你。
  • DNS 是電話簿。A 和 CNAME 管網站、MX 管收信、TXT 管驗證。改了要等，不要一直改。
  • 子網域不用另外付錢，拿來把功能分開：預約一個門、後台一個門。
  • 小鎖頭放在 Cloudflare 上會自動發、自動續，但它只管連線，不管頁面裡放了什麼。
  • 動 DNS 之前先留底；MX 和 TXT 不准隨便動。
