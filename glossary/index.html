術語字典

上一頁的常見問題，是動手時卡住會問的事；這一頁收的是更前面一步：看不懂的詞。全書出現過的術語，加上幾個 Claude 常講、正文沒細講的詞，都在這裡。每一條一句白話、一個比喻，後面標著在哪一章講；那一章換了說法的，括號裡註明那裡怎麼叫。

這頁不用從頭讀，遇到不懂的詞再來查。看得懂術語是入門，第二章到第六章講的就是這一層；這本書真正要練的，是聽到 Claude 說「我在後端加一個欄位」時，你知道它動到哪一塊、有沒有越過邊界。查字典是為了聽得懂這種話。

怎麼查
電腦按 Ctrl + F（Mac 是 Cmd + F），手機用瀏覽器選單裡的「在網頁中尋找」，打中文或英文都找得到。不知道該搜什麼，就從下面的分類點進去。分類大致照全書章節的順序排。

AI 與下指令

AI 是什麼東西、怎麼跟它講話、怎麼開工。

術語 一句白話 比喻
大型語言模型LLM Claude、ChatGPT 這類 AI。做的事是根據前面的字，猜下一個字最可能是什麼。見第二章 讀過整座圖書館的鸚鵡，很會接話，不保證對
指令Prompt 你交給 AI 的那段話。講清楚目標、邊界、情境，結果才會對。把指令寫好的功夫，叫 Prompt Engineering。見第三章 工作交辦單
Token（AI 計費單位） AI 切文字的小塊，不是一個字也不是一個詞。大部分 AI 服務照它算錢，你送出去的、它回你的都算。見第二章 計程車跳表，講越多跳越多
上下文視窗Context Window 一次對話能同時攤開多少東西：你說的、它回的、它讀過的檔案都在上面。每一輪它都重讀一次，對話越長，品質越容易往下掉。見第二章 辦公桌，桌子大也別亂堆
幻覺Hallucination AI 一本正經地講錯，講錯的口氣跟講對的一樣有自信。見第二章 考生不會寫，硬掰一個看起來很像的答案
訓練資料Training data 模型讀過的東西。有截止日，也不會有你公司的客戶和規矩。見第二章 鸚鵡讀過的那座圖書館
先查再答RAG 先把你的資料給它、再叫它回答，不是只靠它讀過的東西。可以減少幻覺，前提是給它的資料是對的。見第二章 從閉卷考變開書考：給它一本公司手冊，讓它翻書回答
向量化Embedding 把一段文字換成一串數字，意思相近的文字，數字也相近。RAG 常用它找出相關段落。正文沒有細講 把每段內容標成地圖上的座標，意思相近的擺得近
微調Fine-tuning 拿自己的資料再訓練模型一次，讓它更像你要的樣子。正文沒有細講 新人職前訓練
代理Agent 能自己拆步驟、用工具、做完再檢查的 AI。Claude Code 就是一種。見第十章 不只回答問題，還會自己動手的助理
樣品屋Demo 先做一個最簡單、用假資料的版本，看過樣子再談細節。見第四章 賣房子先蓋樣品屋

Token 有兩個意思
講 AI 的時候，Token 是切文字、算錢的單位（這一節）。講登入的時候，Token 是登入後拿到的通行證（見前後端邊界與安全那一節）。看到這個詞，看上下文判斷是哪一個。

網址與網頁

說得出檔案在哪、網址哪一段、畫面哪一塊。

術語 一句白話 比喻
根目錄Root directory 專案資料夾，所有東西都住在裡面。見第五章 你家大門
路徑Path 檔案在哪裡、怎麼走。絕對路徑從最上層講起；相對路徑從現在的位置走，./ 是這裡、../ 是往上一層。放上網的頁面，圖片要用相對路徑。見第五章、第七章 外送地址：完整地址，或「三樓左轉第二間」
路由Route 網址後半段，說進了網站之後走到哪，例如 /products/123。見第五章 進大樓之後走到哪一間
查詢參數Query parameter 網址 ? 後面的條件，例如 ?color=red。見第五章 跟櫃檯說「只要紅色的」
副檔名File extension 檔名最後的 .html、.css、.js，告訴你這是哪一種檔。見第五章（那裡也叫「後綴」） 檔案夾上的分類貼紙
HTML 網頁的骨架和文字。見第五章、第六章 Word 文件
CSS 網頁的外觀：顏色、大小、間距、排版、動畫。見第六章 簡報的佈景主題
JavaScriptJS 網頁的動作：按了會怎樣。見第五章、第六章 Excel 的巨集
頁面部位Header、Navbar、Hero、Footer 頁首、導覽列、首頁第一眼的大圖大標題、頁尾。叫得出名字，才指得到要改哪裡。見第六章 房子的天花板、門口、客廳、地板
元件Component 可以重複用的畫面零件：按鈕、卡片、下拉選單、跳出來的框。見第六章（元件圖鑑那段） 樂高積木塊
響應式設計RWD 同一個網頁，在手機和電腦上自動換一種排法。見第六章 同一份菜單，印成大海報和小卡兩種版
開發者工具DevTools 網頁上按右鍵選「檢查」，或按 F12 打開，看某一塊叫什麼名字、套了哪些樣式、有沒有紅字錯誤。見第六章、第十章 牆打開看得到的管線圖
多國語言i18n internationalization 的縮寫（i 和 n 中間有 18 個字母），讓同一個網站能切換不同語言。見第三章 同一本菜單印中、英、日三種版

部署

把做好的頁面放上網，改了怎麼重新上線，改壞了怎麼退。

術語 一句白話 比喻
部署Deploy 把做好的檔案，放到一台一直開著、大家都連得到的機器上，再配一個網址。在你電腦上打得開，不等於別人打得開。見第七章 把傳單從書桌放到街口的架子上，誰經過都能拿
純靜態頁面Static site 只有 HTML、CSS、JS 檔案的網站。做好就放著，每個打開的人拿到的都是同一份；改完直接上傳，不用打包。這本書推薦從這裡開始。見第七章、第十一章 印好放在架上的傳單，不用有人顧
本機網址localhost 意思是「這台電腦自己」。Claude 做好給你看的網址如果是 localhost 或 file:// 開頭，只有你的電腦打得開，傳給別人沒用。見第七章 還躺在你書桌上的傳單
Cloudflare Workers／Pages Cloudflare 放網站的兩個服務。新專案用 Workers，舊專案留在 Pages 也行。沒接自己的網域前，網址分別長得像 名字.你的子網域.workers.dev 和 專案名.pages.dev。見第七章、第十一章 租現成的店面，檔案搬進去就開張
wrangler Cloudflare 的官方 CLI，負責登入、上傳、退版。見第七章 專管 Cloudflare 的那位師傅
設定檔wrangler.jsonc 放在專案最外層，告訴 Cloudflare 網站叫什麼、哪個資料夾要放上網。只指定要上網的那個資料夾，筆記和金鑰就不會被一起送出去。見第七章 交給架子管理員的上架清單
自動部署Workers Builds 讓 Cloudflare 盯著 GitHub 上的專案，main 有新版本推上去，就照設定檔自動再部署一次。接上之後，就不要再從自己電腦直接上傳。見第七章 訂報紙：新的一期出刊，就自動送到門口
自動測試與部署CI/CD 程式碼推上去之後，自動跑測試、自動上線。上面那個自動部署，就是很陽春的一種。見第七章 工廠的自動化產線
退版Rollback 新版有問題，把網站換回之前的某一版。退的是頁面和程式，資料不會跟著退；GitHub 那邊也要另外 revert，不然下次推上去壞的又回來。見第七章 架上的傳單印錯了，先把上一版放回去止血

網域

網址的門牌怎麼買、怎麼接，順便收信。

術語 一句白話 比喻
網域Domain 網站的門牌，例如 example.com。門牌和放網站的地方分開買，再接起來。網域是按年租的，到期要續約，忘了續會被收回。見第五章、第八章 門牌，不是房子：可以換房子掛，房子也能掛好幾塊
頂級網域TLD 網址最後面那一段，例如 .com、.tw。它決定你能不能買、去哪裡買。.com.tw 嚴格說是 .tw 底下再分出來的一層，買的時候當成一種結尾看就好，要有公司、行號這類登記才能買。見第五章、第八章 門牌最後面的縣市名
網域註冊商Registrar 賣網域的店。同一個網址在哪一家買都一樣，差在價錢、續約價、介面、能買哪些結尾。.tw 系列要找 TWNIC 名單上的台灣註冊商。見第八章 代辦門牌的櫃台
IP 位址IP address 網路上每台機器的號碼。人記網域，電腦靠 IP 找到機器。見第五章、第八章 大樓的座標
網域解析DNS 把網域翻成 IP 位址的系統。買了網域，就在這本電話簿裡有一頁自己的格子。改了不會馬上全世界生效，要等，不要一直改。見第八章 電話簿：查名字找到號碼
DNS 紀錄DNS record DNS 電話簿裡的一行，寫著這個名字要去哪裡。常見的有 A、CNAME、MX、TXT 四種。見第八章 電話簿上的一行
A 紀錄A record 這個名字對到哪個 IP 位址。AAAA 是同一件事的新版（IPv6）號碼。用 Cloudflare 的話，多半它自己會處理。見第八章 電話簿上直接寫號碼
CNAME 紀錄CNAME 這個名字是另一個名字的別名：「查我，請去查它」。見第八章 「找我，請打總機」
MX 紀錄MX record 寄到這個網域的信，要送到哪個郵件伺服器。被蓋掉或刪掉，網站照樣打得開，只是信寄不進來，常常好幾天才有人發現。見第八章 郵局登記的收件地址
TXT 紀錄TXT record 一段文字，多半是給別的服務驗證「這個網域真的是你的」。信箱服務要你加的 SPF、DKIM、DMARC 也是 TXT，用來證明信真的是從這個網域寄出的，少了容易被丟進垃圾信匣。見第八章 門口貼的「本店負責人」證明
名稱伺服器Nameserver 這本 DNS 電話簿放在誰家。網域在台灣註冊商買、要交給 Cloudflare 管，就是到註冊商那邊把它改成 Cloudflare 給的那兩個。見第八章 電話簿放在哪一個管理處
子網域Subdomain 網域前面多加的一段，例如 book.example.com 的 book。買了一個網域，前面加什麼都不用再付錢，拿來把功能分開：預約一個門、後台一個門。見第五章、第七章、第八章 大樓裡的哪個部門
加密連線與憑證HTTPS、SSL／TLS 憑證 網址開頭是 https:// 的連線，傳的東西路上別人看不到，網址列有小鎖頭。網站要拿出一張憑證，證明自己就是這個網址；放在 Cloudflare 上會自動發、自動續。小鎖頭只管連線，不管頁面裡放了什麼。見第八章 密封的信封，加上店門口掛的營業登記證

資料庫

開一個資料庫接到頁面，誰能做什麼、怎麼備份。

術語 一句白話 比喻
資料庫Database 存資料的地方，裡面分好幾張表。跟試算表不同：它會擋錯、會看人、不怕擠。見第九章、第十五章 有管理員的登記處：單子遞進去，他先看格式和資格才歸檔
Supabase 現成的後端服務，底層是 PostgreSQL：資料庫、會員登入、檔案存放都有。免費版同時最多 2 個專案、沒有自動備份，一週沒動靜會被暫停。見第九章、第十一章 自帶管理員的檔案櫃，不用自己架伺服器
Cloudflare D1 Cloudflare 自己的資料庫。免費版每個資料庫 500 MB、整個帳號合計 5 GB、每天 500 萬列讀取。不能從頁面直接連，要經過一支 Worker 小函式。見第九章、第十一章 跟店面同一個房東租的檔案櫃，少管一個帳號
授權（資料表）Grant 決定從頁面來的人，能對一張表做哪幾種動作：讀、新增、修改、刪除。沒授權的動作，門根本不開。見第九章、第十二章 店門口的告示：「本店只收預約單」
訪客身分anon Supabase 對「沒登入的人」的叫法。打開頁面的客人，都是這個身分。見第九章 沒報名字的路人
存取規則Row Level Security（RLS） 設在資料庫上的規則，一筆一筆決定這個人准不准。打開之後，沒寫規則的動作一律擋掉；用 SQL 開表時要記得自己打開。頁面直接連 Supabase，就靠它把關。見第九章、第十三章、第十六章 櫃檯店員手上的檢查表，倉庫每一格的門禁
可公開金鑰Publishable key Supabase 給頁面用的金鑰，開頭是 sb_publishable_。放在頁面上沒關係，反正誰都看得到；拿著它能做什麼，全看授權和存取規則。舊專案叫 anon key。見第九章、第十六章 店門口的門鈴：誰都能按，開不開門看規則
最高權限金鑰Secret key Supabase 的管理用金鑰，開頭是 sb_secret_，存取規則擋不住它。只能放在後端，不放頁面、不進 GitHub；外流了先到後台作廢、換一把新的。舊專案叫 service_role key。見第九章、第十六章 店裡的萬用鑰匙，拿到就能開每一個抽屜
備份Backup 把資料庫匯出一份，存到別的地方。Supabase 免費版沒有自動備份，要自己定期做。沒試過還原的備份，不算備份。見第九章 帳本影印一份，放進別處的保險箱
專案暫停Pause Supabase 免費專案一週沒動靜會被暫停，客人按送出會失敗。到後台按 Resume project 恢復；正式給客人用的，就考慮付費。見第九章 太久沒人來的攤位，管理處先拉下鐵門

兩把金鑰，一句話分清楚
publishable key 可以放頁面，因為把關靠的是存取規則，不是把金鑰藏好；secret key 存取規則擋不住，只能放後端。Claude 說「用 secret key 比較簡單」，就是它要越過邊界了。細節在第九章 資料庫和第十六章 前後端邊界。
同一個「授權」，三種意思
這本書裡「授權」出現在三個地方，意思不一樣：
授權條款（License）：別人的程式碼你能怎麼用（版本控制與 GitHub那一節）。
授權（Grant）：資料表開放哪幾種動作（資料庫那一節）。
授權登入：wrangler、gh 第一次用，要你在瀏覽器按同意，讓它用你的帳號做事（第七章）。

Claude Code 與工具

它怎麼動手、你怎麼替它畫線，還有做影片、管筆記的工具。

術語 一句白話 比喻
終端機Terminal 打字下指令的那個視窗。見第七章、第十章 電腦的對講機，不用滑鼠，用打字跟電腦說話
命令列工具CLI Command Line Interface，在終端機裡用打字操作的工具。claude、gh、wrangler 都是 CLI。見第七章、第十章、第十一章 對講機另一頭的師傅：喊 gh 找管 GitHub 的，喊 wrangler 找管 Cloudflare 的
Claude Code 會自己開檔案、改檔案、跑指令、上網查的 AI。在終端機打 claude 叫出來的是它的 CLI 版。見第十章 請來的師傅：你講要什麼，他動手，你驗收

CLI、MCP、瀏覽器工具、Computer Use，先用哪個
有官方 CLI 的先用 CLI，例如 GitHub 的 gh、Cloudflare 的 wrangler、Supabase 的 supabase。沒有 CLI 才裝 MCP（連接器）。操作網頁交給瀏覽器工具。都不行才用 Computer Use。

跟 Claude 這樣說就好：「這件事有官方 CLI 就用 CLI 做，沒有再用 MCP。」理由在第十章 Claude Code 怎麼用、第十一章 技術棧和第十八章 其他工具。

框架和工具庫差在哪
框架規定你怎麼寫：檔案放哪、網址怎麼走，你在它的骨架裡填東西。Next.js 是框架。
工具庫是你要用什麼就拿什麼，主導權在你。例如 lodash，要用它的哪一個函式就拿哪一個。

差別在誰說了算。用框架，邊界有一部分是它替你畫的；換掉它，幾乎等於重蓋。這也是第十一章 技術棧建議先從純靜態頁面開始的原因之一：上線的東西你看得懂，邊界才是你畫的。

這頁帶走什麼

  • 不用背。看到不懂的詞，回來查一句白話、一個比喻就夠。
  • 知道那個詞是什麼意思，跟 Claude 就少繞好幾輪，也省 Token。
  • 每個詞後面的章節，是它真正派上用場的地方。查完想知道「這跟我有什麼關係」，就點過去。標著「正文沒有細講」的，認得名字就夠，Claude 提到時請它用白話講。
  • 詞是入門。聽得懂之後，要問的是：這一步動到哪一塊、那一塊能不能動。

跟 Claude 怎麼說

  • 「你剛剛用到的這幾個詞，各用一句白話加一個比喻講給我聽。」
  • 「這次的改動，用『頁面、後端、資料庫、外部服務』這四塊說明你動到哪幾塊。」
  • 「回覆我的時候，第一次出現的英文術語後面加上中文。」
