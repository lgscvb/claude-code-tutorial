第七章

部署：把網站放上網

上一章練的是把想要的畫面講清楚。這一章拿一個真的例子來用：先請 Claude 做出一個頁面，再把它放上網，讓客人拿手機就打得開。之後改了內容也知道怎麼重新上線、改壞了怎麼退回去。

接下來三章用同一個例子：B 咖啡店要一個「線上預約表」頁面。客人填姓名、電話、日期、時間、人數和備註，按送出。這個頁面還不存在，下面第 0 步會先請 Claude 做出來。

  • 這一章（第七章）：把預約表頁面放上網，拿到一個別人打得開的網址
  • 第八章：把那串網址換成 B 咖啡店自己的網址
  • 第九章：讓客人按下送出的預約，真的存進資料庫

所以這一章做完，表單看得到、填得了，但按送出還不會存。這是故意的：一次只多一塊，哪裡出問題你才找得到。

什麼叫部署：把傳單從書桌放到街口的架子上

比喻：你在家裡書桌上做好一張傳單，排版漂亮、字也校對過了。可是它躺在書桌上，路人看不到。

部署就是把傳單拿到街口的架子上，誰經過都能拿一張。

你的電腦＝書桌。關機、闔上螢幕、帶出門，別人就連不到。
放網站的服務（這一章用 Cloudflare）＝街口的架子。一直都在，全世界連得到。
網址＝告訴別人架子在哪裡。

白話講：部署就是把做好的檔案，放到一台一直開著、大家都連得到的機器上，再配一個網址。

「在我電腦上打得開」跟「別人打得開」是兩件事。Claude 做完頁面給你看的時候，網址常常是 localhost 開頭，或是 file:// 開頭的一串路徑。那是你書桌上的東西，傳給朋友，他那邊打不開。

很常見的誤會
把 localhost 的網址貼給同事，說「做好了你看一下」。localhost 的意思是「這台電腦自己」，同事打開會連到他自己的電腦，當然什麼都沒有。要給別人看，得先部署。

先看全貌：從你的電腦到客人的手機

整條路只有四站。先看一次，後面每一步都在這張圖上的某一段。

為什麼純靜態頁面好部署

B 咖啡店的預約表，本身就是一張純靜態頁面：HTML 管內容、CSS 管長相、JS 管按下去之後的動作。「靜態」的意思是，檔案做好就放著，每個打開的人拿到的都是同一份。

第十一章會把「什麼需要一直跑、什麼不用」整個攤開來講。這裡先借那一章的兩句比喻：

靜態網站＝傳單。印好放在架子上，有人來就拿走看，不用有人顧。

VM（在雲端租一台一直開著的電腦）＝請一個人 24 小時站櫃檯。沒客人也要付薪水。

傳單比櫃檯好處理太多了：

  • 沒有打包這一步：改完就上傳，上傳的就是你看到的那幾個檔，不用等
  • 不會睡著：沒有一台機器要開著等客人，也就不會有「第一個客人要等一分鐘才打得開」這種事（後面講 Render 時會看到）
  • 便宜：Cloudflare 對靜態檔案被瀏覽不收費、不限次數
  • 你看得懂：資料夾裡有哪些檔，網站上就是哪些檔，沒有中間的魔術

請 Claude 做網站，它常會順手選 Next.js，或是 React、Vue 加打包工具。這類做法都要先打包才能上線，我不推薦：每改一次都要等打包，用到的套件還要一直跟著升級；部署出問題時，你也看不出是哪一層壞了。純靜態頁面改完直接上傳就好。

跟 Claude 怎麼說
「這個預約表用純 HTML、CSS、JS 做，不要用需要打包的框架。做好之後要能直接部署到 Cloudflare。」

開工前：要準備什麼、誰來做

整章的分工只有一條原則：打字、下指令、寫設定檔、看錯誤訊息，交給 Claude；用你的名字簽的東西，你自己來。註冊帳號、登入、按允許、付款、輸入驗證碼，都是後者。這些 Claude 不該替你做，很多也做不了。

要準備的 誰來 說明
Claude Code 你（裝一次） 裝法和基本用法見第十章
Cloudflare 帳號 你 放網站的地方。第 2 步註冊
GitHub 帳號 你 存程式碼和每一版紀錄的地方。第 6 步才用到
Node.js Claude wrangler 要靠它才能跑。電腦沒有的話，Claude 會說要先裝
wrangler Claude Cloudflare 的官方 CLI，第 3 步裝
Git Claude（跳視窗時你按） 在你電腦上記下每一版修改的工具，第 6 步用到。Mac 第一次用，系統會跳出視窗問要不要安裝開發者工具（Command Line Tools），按「安裝」，等它跑完再叫 Claude 繼續
gh Claude GitHub 的官方 CLI，第 6 步裝

複習一下兩個詞：終端機是打字下指令的那個視窗；CLI 是在終端機裡用打字操作的工具。claude、gh（GitHub 的）、wrangler（Cloudflare 的）都是 CLI。這一章幾乎每件事都靠這三個完成，不用裝 MCP。

「你在電腦上的工作，幾乎 99% 都可以丟給它自己處理。」

丟給它的是動手。做到哪裡為止、哪裡不准碰，還是你要定。這一章後面「哪裡有邊界」那一節，就是在講這條線畫在哪。

新版 Claude Code 在終端機預設是 Auto 模式：多數指令不會先問你，有風險的才會被另一個把關的模型攔下來。第一次部署，想每一步都先看過再放行，按 Shift + Tab，直到輸入框下方出現 manual mode on（見第十章步驟 6）。之後它每次要跑指令都會先問你，看一眼它要跑什麼再按，看不懂就問它「這行在做什麼」。

第一次放上網：先做出頁面，再走七個步驟

第 0 步先請 Claude 把預約表做出來；第 1 到第 7 步把它放上網。每一步都分成五格：

  • 要做什麼：這一步的目的
  • 跟 Claude 怎麼說：可以直接複製的一句話
  • 你自己動手：Claude 不該、也不能替你做的事
  • 做完會看到：用來確認自己有沒有做對
  • 常見卡住：卡住時怎麼辦

畫面上的按鈕名稱照 Cloudflare、GitHub 官方文件寫（2026-11-13 查）。服務商改版後名字可能不同，對不上就把畫面截圖給 Claude，問它現在該按哪裡。

第 0 步

開一個資料夾，請 Claude 做出預約表

要做什麼

給這個網站一個專用的資料夾，在裡面啟動 Claude Code，請它做出 B 咖啡店的預約表頁面。後面七步都在這個資料夾裡做。

  1. 在桌面開一個新資料夾，取名 b-cafe-booking（英文小寫加連字號，後面設定檔也用這個名字）。
  2. 打開終端機，走進這個資料夾，打 claude 啟動。還沒裝 Claude Code、不知道終端機怎麼開，照第十章「照著做：從安裝到第一個任務」的步驟 2 到 4 做，做完回來這裡。
跟 Claude 怎麼說
「幫我做 B 咖啡店的線上預約表頁面，欄位有姓名、電話、日期、時間、人數、備註，用純 HTML、CSS、JS，不要用需要打包的框架。這一版先不用存資料，按送出顯示『已收到預約』就好。做好打開給我看。」
你自己動手
看它做出來的頁面。哪裡不像你要的，用第六章學的名字跟它說，例如「時間改成下拉選單，只列營業時段」「送出按鈕放大一點，手機上比較好按」。改到你覺得可以，再往下一步。
做完會看到
資料夾裡多了 index.html，可能還有 styles.css、script.js。瀏覽器打開，看得到一張可以填的預約表。
常見卡住
  • 打 claude 出現 command not found：還沒裝好，回第十章步驟 3。
  • 它說要先裝一堆套件、跑 npm install：代表它選了要打包的做法。跟它說「改用純 HTML、CSS、JS，不要框架」。
第 1 步

把頁面整理好，自己先看一遍

要做什麼

把要放上網的檔案集中到一個資料夾，首頁叫 index.html。筆記、草稿、設定檔留在外面，不要放進這個資料夾。

原因很簡單：這個資料夾裡的每一個檔，上線後任何人都拿得到。

跟 Claude 怎麼說
「幫我把剛才做好的預約表整理成可以部署的樣子：要上網的檔案放在 public 資料夾，首頁叫 index.html，圖片和樣式都用相對路徑。整理完列出資料夾裡有哪些檔，再打開給我看。」
你自己動手
在瀏覽器裡看一遍：字對不對、營業時段對不對、手機寬度排得好不好（請 Claude 教你把瀏覽器縮成手機寬度）、每個按鈕按得到。內容對不對，只有你知道。
做完會看到
一個 public 資料夾，裡面至少有 index.html，可能還有 styles.css、圖片。這時的預覽網址是 localhost 或 file:// 開頭，只有你的電腦打得開。
常見卡住
  • 在你電腦上有圖，上線後破圖：圖片路徑寫成你電腦裡的完整位置（像 /Users/你的名字/桌面/…）。跟 Claude 說「圖片路徑都改成相對路徑」。路徑是什麼，見第五章「根目錄與路徑」。
  • Claude 說要先跑 build 才能看：代表它做成要打包的專案了。把上一節那句話再講一次，請它改回純靜態頁面。
第 2 步

註冊 Cloudflare 帳號

要做什麼
開一個 Cloudflare 帳號。這是街口的架子，用你的名字租。
跟 Claude 怎麼說
這一步不用它。註冊完跟它說：「Cloudflare 帳號註冊好了，接下來帶我把預約表放上去。」
你自己動手
  1. 到 dash.cloudflare.com/sign-up，填 Email 和密碼，按 Create Account。
  2. Cloudflare 會自動寄一封驗證信到你的信箱，點信裡的連結完成驗證。

密碼用密碼管理工具產生、存起來。幫公司做的話，用公司的信箱註冊，不要用你私人的。哪天換人接手，帳號才交得出去。

做完會看到
登入後進到 Cloudflare 的後台（dashboard）。後台裡有一個叫 Workers & Pages 的頁面，後面幾步會一直回來這裡。
常見卡住
  • 驗證信沒收到：先看垃圾信件匣，再確認 Email 有沒有打錯。
  • Claude 問你密碼：不用給，它也不需要。下一步登入是在瀏覽器裡由你自己按的。
第 3 步

讓 Claude 裝 wrangler，登入你的帳號

要做什麼
wrangler 是 Cloudflare 的官方 CLI。裝好、登入一次，Claude 之後就能用打字的方式，替你把檔案送上 Cloudflare。
跟 Claude 怎麼說
「幫我在這個專案裝 wrangler，用 Cloudflare 官方文件現在建議的方式。裝好之後跑 wrangler login，瀏覽器跳出來我自己按。登入完用 wrangler whoami 確認登的是哪個帳號。」
你自己動手
  • 電腦還沒有 Node.js 的話，Claude 會先說要裝。安裝過程如果跳出視窗要你輸入電腦的登入密碼，那個你自己打，不要打在對話框裡給 Claude。
  • wrangler login 會打開瀏覽器，進到 Cloudflare 的授權頁。先確認頁面上是你第 2 步註冊的那個帳號，再按同意授權。
做完會看到
瀏覽器顯示授權完成。回到終端機，wrangler whoami 印出你的 Email，表示 Claude 現在可以用這個帳號做事了。
常見卡住
  • 瀏覽器沒有自己打開：終端機裡會印出一串網址，複製貼到瀏覽器，一樣能授權。
  • 登到別人的帳號（例如電腦上之前登過家人或前同事的）：跟 Claude 說「先 wrangler logout，再重新登入」。
  • 出現 command not found 或找不到 npm：電腦還沒有 Node.js。不用自己查，請 Claude 看錯誤訊息、處理好再繼續。
第 4 步

寫設定檔：告訴 Cloudflare 要放哪些檔

要做什麼

在專案最外層放一個設定檔 wrangler.jsonc。Cloudflare 官方建議新專案用這種格式。它只交代三件事：網站叫什麼、用哪一天的規則、哪個資料夾要放上網。

{ // 網站在 Cloudflare 裡的名字，也是網址最前面那一段 "name": "b-cafe-booking", // 用哪一天的 Cloudflare 規則，填建立當天的日期 "compatibility_date": "2026-11-13", "assets": { // 只有這個資料夾會被放上網 "directory": "./public" } }
  • name：用英文小寫加連字號（-），不要用中文和空格。
  • compatibility_date：Cloudflare 照這個日期決定用哪一版的執行環境。填一次就好，之後不用常改。
  • assets.directory：只把 public 放上網。設定檔、筆記，還有之後可能出現的金鑰檔都不在裡面，就不會被一起送出去。
  • 沒有 main 這一行：main 指的是後端小程式的入口。只放頁面的網站可以不寫。
跟 Claude 怎麼說
「幫我寫 wrangler.jsonc：只放靜態頁面，不要 Worker 程式；名字叫 b-cafe-booking；只上傳 public 資料夾；compatibility_date 填今天。寫完一行一行用白話跟我說它在做什麼，然後用 wrangler dev 在本機跑一次給我看。」
你自己動手
看 Claude 的解釋，確認 directory 指的是 ./public，不是整個專案資料夾（寫成 . 或 ./ 就是整個專案）。這一格寫錯，整個專案都會被放上網。
做完會看到
專案最外層多了 wrangler.jsonc。wrangler dev 給你一個本機網址，打開跟第 1 步看到的一樣。
常見卡住
  • Claude 寫成 wrangler.toml：也能用，舊專案很多是這種。新專案請它改成 wrangler.jsonc，兩種不要同時存在。
  • Claude 多加了 main 和一個 src/index.js：它以為你要後端。跟它說「這一章只放頁面，先拿掉」。什麼時候才需要後端，第十六章會講。
第 5 步

第一次上傳，拿到網址

要做什麼
跑 npx wrangler deploy。wrangler 會把 public 裡的檔案送上 Cloudflare，給你一個網址。
跟 Claude 怎麼說
「部署到 Cloudflare，完成後把網址給我。」
你自己動手
拿出手機，關掉 Wi-Fi、改用行動網路，打開那個網址。用手機網路打得開，才是真的「別人也打得開」。再傳給一個朋友試試看。
做完會看到

終端機最後印出一個網址，長得像：

https://b-cafe-booking.你的子網域.workers.dev

手機上看到預約表。Cloudflare 後台的 Workers & Pages 頁面裡，多了一個 b-cafe-booking。

常見卡住
  • 打開是空白或 404：public 裡的首頁不叫 index.html，或設定檔的 directory 指錯資料夾。請 Claude 對照第 4 步檢查。
  • 中間那段子網域不是你想要的：那是整個帳號共用的名字。到後台 Workers & Pages 頁面，在 Your subdomain 旁邊按 Change 改。趁還沒把網址給客人之前改。
  • Claude 說要先 npm run build：代表它做成要打包的專案了，回到第 1 步。

做到這裡，網站已經在網路上了。後面兩步是讓它好維護：存一份到 GitHub，再讓它自動更新。

第 6 步

存一份到 GitHub

要做什麼

GitHub 是放程式碼和每一版修改紀錄的地方。一個專案在 GitHub 上叫一個 repo。存上去有兩個好處：電腦壞了東西還在；下一步可以讓 Cloudflare 盯著它，自動更新網站。

兩個動詞先認識：commit 是在你電腦上存一個版本，寫一句這次改了什麼；push（推上去）是把這些版本送到 GitHub。

順序是：你先到 GitHub 註冊帳號，再請 Claude 裝 Git 和 gh、用 gh 登入、建 repo、推上去。

跟 Claude 怎麼說
先註冊好 GitHub 帳號（見下一格），再說：「GitHub 帳號註冊好了。幫我確認電腦有沒有 Git 和 gh，沒有就用官方建議的方式裝。裝好用 gh 幫我登入 GitHub，瀏覽器跳出來我自己按。登入好之後，建一個私人的 repo 叫 b-cafe-booking，把這個專案推上去。推之前先列出會上傳哪些檔給我看，node_modules、.env 和任何金鑰都不要推。」
你自己動手
  • 先註冊 GitHub：到 github.com/signup，或選 Continue with Google 用 Google 帳號註冊，照畫面走。過程中要驗證 Email。GitHub 強烈建議開兩步驟驗證，開。
  • Mac 跳出安裝開發者工具的視窗：第一次用 Git 時，系統可能問你要不要安裝 Command Line Tools。按「安裝」，等它跑完，再跟 Claude 說「裝好了，繼續」。
  • 登入授權：gh auth login 會帶你到瀏覽器授權，有時會給你一組一次性的代碼，要你在瀏覽器裡輸入。代碼你自己輸入。
  • 看清單：Claude 列出要上傳的檔，掃一眼有沒有你不想給人看的東西。
  • 選私人：公開 repo 的程式碼，任何上得了 GitHub 的人都看得到。B 咖啡店的預約表沒有理由公開。
做完會看到
瀏覽器打開 github.com/你的帳號/b-cafe-booking，看得到 public 資料夾和 wrangler.jsonc，這個 repo 標示為私人（Private）。
常見卡住
  • 不小心建成公開：請 Claude 用 gh 改成私人。但改之前別人已經複製走（fork）的，GitHub 官方說會繼續公開，收不回來。
  • 推上去才發現有金鑰：刪掉那個檔不夠，舊版紀錄裡還在。那把金鑰要到發它的服務那邊作廢、換一把新的。這件事你要自己確認做完。
第 7 步

接上 GitHub：以後推上去就自動上線

要做什麼
讓 Cloudflare 盯著 GitHub 上的 b-cafe-booking。只要 main 這條主線有新的修改推上去，它就照 wrangler.jsonc 自動再部署一次。這叫自動部署，Cloudflare 把這個功能叫 Workers Builds。
跟 Claude 怎麼說
「我要在 Cloudflare 後台把 b-cafe-booking 接上 GitHub 的 b-cafe-booking repo。照官方文件告訴我每一格要填什麼：分支、打包指令（Build command）、部署指令。我自己去按。」
你自己動手
  1. 後台 Workers & Pages → 點 b-cafe-booking → Settings → Builds → Connect。
  2. 第一次接，會要你在 GitHub 上授權 Cloudflare 的 GitHub App（Cloudflare Workers & Pages）。能選的話選 Only select repositories，只勾 b-cafe-booking，不要整個帳號都給。
  3. 分支選 main。打包指令（畫面上叫 Build command）是選填，純靜態頁面沒有打包這一步，留空。部署指令預設就是 npx wrangler deploy，不用改。
做完會看到
請 Claude 改一個字、commit、推上去。過一下，後台這個 Worker 底下出現一筆新的部署紀錄，成功之後網址上的頁面跟著變。
常見卡住
  • 自動部署失敗，紀錄裡說名字對不上：後台的 Worker 名字，要跟 wrangler.jsonc 裡的 name 一模一樣。
  • 授權時選錯 GitHub 帳號：到 GitHub 設定裡的 Authorized GitHub Apps 頁面撤銷授權，再接一次。
  • 推了但網站沒變：先看是不是推到 main 以外的分支。其他分支不會改到正式網址，而是產生一個預覽版本，網址在這個 Worker 的 Previews 區塊。這其實好用：想先給老闆看再上線，就推到別的分支。

改了內容，怎麼重新上線

接上 GitHub 之後，改內容固定走這一條路：

  1. 跟 Claude 說要改什麼
  2. 它改完，先在你的電腦上看過
  3. 你說可以，它才 commit、推上 GitHub
  4. Cloudflare 自動部署，你用手機打開確認
跟 Claude 怎麼說
「把預約表的營業時段改成早上九點到晚上六點。改完先在本機給我看，我說可以，再 commit、推上 GitHub。」

還沒接 GitHub 的話，改完請 Claude 再跑一次 npx wrangler deploy 就好。

兩條路只走一條
接上 GitHub 之後，就不要再從你的電腦直接 wrangler deploy。不然網站上的版本跟 GitHub 上的不一樣；下一次有人推上去，你從電腦上傳的修改就被蓋掉了。同一份東西放兩個地方、各改各的，正是第十七章「單一資料來源」那一節講的壞法。

跟 Claude 說一次就好：「這個專案已經接上 GitHub 自動部署，以後一律推上 GitHub，不要直接 wrangler deploy。」也可以請它把這句寫進專案的 CLAUDE.md，以後每次開工它都會先讀到。

改了卻沒看到變化？先重新整理頁面。瀏覽器有時會拿它之前存的舊檔給你看；新版本傳到世界各地的機器上，也需要一點時間。等一下再看，還是沒變，再請 Claude 查後台的部署紀錄有沒有失敗。

改壞了，怎麼退回上一版

比喻：架子上的傳單換錯了，印錯營業時間。先把上一版放回架上止血，再回家把錯的那張改好。兩件事都要做，只做第一件，下次補貨又會補到錯的那張。

第一件：Cloudflare 上先退版（止血）

Cloudflare 會記住你每一次部署的版本，可以直接換回之前的。兩種方式擇一：

  • 後台：Workers & Pages → 點 b-cafe-booking → Deployments → 在要退回的那一版打開三個點的選單 → Rollback
  • 指令：請 Claude 跑 npx wrangler rollback，它會列出最近的版本讓你挑

官方文件寫明只能退回最近發布的 100 個版本。一般小網站很夠用。

第二件：GitHub 上也要退（根治）

Cloudflare 退版，只換掉架子上那一份，GitHub 上壞掉的那個版本還在。下次有人推上去，壞的又跟著上線。所以止完血，要請 Claude 在 Git 裡把壞掉的那次修改退掉（這個動作叫 revert，它會新增一個「把那次修改反過來」的版本，舊紀錄都還在）。

跟 Claude 怎麼說
「網站壞了。先用 wrangler rollback 退回上一個正常的版本，退之前跟我確認是哪一版。再在 Git 裡把壞掉的那次修改 revert 掉，推上去之前先給我看。」
退版退不到的東西
退版只換頁面和程式，不會把資料退回去。Cloudflare 官方文件也寫了：連接的資料庫這類資源不會跟著退。

現在的預約表還沒有資料庫，沒差。到第九章接上資料庫之後要記得：如果新版本改過資料的樣子（例如多了一個欄位），退回舊頁面反而可能出錯。資料的樣子怎麼改才不會出事，見第十五章。

為什麼網址是一串 xxx.workers.dev

第 5 步拿到的網址長這樣：

https://b-cafe-booking.你的子網域.workers.dev
比喻：你在一個大市集裡租了攤位。地址是「市集名字＋你的區＋攤位名稱」。

workers.dev＝Cloudflare 這個市集的名字
你的子網域＝你的帳號在市集裡的那一區，整個帳號共用
b-cafe-booking＝攤位名稱，就是設定檔裡的 name

用 Cloudflare Pages 放的網站，網址則是 專案名.pages.dev，道理一樣。

這種網址能用，但有三個問題：長、不好記、看起來不像正式店家。Cloudflare 自己的文件也說，workers.dev 適合個人或興趣專案，正式上線建議用自己的網域。

下一章就做這件事：幫 B 咖啡店買一個自己的網域（網址的門牌），再到這個 Worker 的 Settings → Domains & Routes 把它接上。接好之後，workers.dev 這個網址可以留著自己測試，也可以關掉。

Cloudflare 的 Workers 和 Pages：選哪個

Cloudflare 有兩個能放網站的服務：Workers 和 Pages。網路上的教學兩種都有，Claude 也可能兩種都提。

  • 新專案用 Workers：Cloudflare 的 Pages 文件首頁現在掛著一句「新專案從 Workers 開始」（Start new projects with Workers），並說 Workers 是它主要的應用程式平台。這一章用的就是 Workers
  • Pages 還能用：舊專案不用急著搬。兩邊的靜態檔案被瀏覽都不計費。Pages 的上傳指令是 npx wrangler pages deploy 資料夾名稱，網址是 專案名.pages.dev
  • 自動部署的免費額度算法不同：Workers 每月 3,000 分鐘，Pages 每月 500 次。純靜態頁面不用打包，兩邊都用得很少

你不用自己研究差別。跟 Claude 這樣說就好：

跟 Claude 怎麼說
「幫我把這個靜態網站部署到 Cloudflare，用官方文件現在建議的方式。動手前先上官方文件查，告訴我你查到的是哪一頁。」

免費額度：放一個預約表要花多少

先講結論：這一章做完，B 咖啡店一毛錢都不用花。要花錢是下一章買網域的時候。

項目 免費版 跟這一章的關係
靜態檔案被瀏覽 免費、不限次數 預約表就是靜態檔案，客人怎麼看都不計費

常用部署工具選擇

你寫好了程式，接下來要讓別人看到。部署就是把你電腦上的東西搬到網路上。能做這件事的服務很多，你一定會聽到其他名字。

先講結論，跟第十一章一樣：網站做成純靜態頁面（HTML、CSS、JS）放 Cloudflare，資料庫用 Supabase（資料單純的話用 Cloudflare D1 也行），版控用 GitHub。大部分小專案用這三樣就夠了。

跟 Claude 怎麼說
「這個網站用純 HTML、CSS、JS 做，不要用需要打包的框架。做好直接部署到 Cloudflare。」

「動手之前，先上 GitHub 找有沒有現成的，找到能用的就不要從零做。」

這三樣各自拿來做什麼、免費額度多少、什麼情況選哪一個，第十一章「我用的組合」整理成一張表和一個簡單判斷法（只要讓人看的網站、要存資料、要定時自動做事，各選哪個），這裡不重複列，數字以那一章為準。

其他你會聽到的名字

下面四個我不會拿來當起點，但你一定會聽到。知道各自適合什麼、免費方案卡在哪就好：

工具 什麼情況才用 免費額度 難度
Vercel 你手上已經有一個 Next.js 專案。它就是做 Next.js 的公司，兩者整合得很好；新專案我不會從這裡開始 有，但免費方案（Hobby）只能做個人、非商業的專案。網站上有賣東西、放廣告，或是收錢幫人做的，都要用付費方案 簡單

Render 免費方案的「休眠」問題
Render 的免費方案，如果 15 分鐘沒人使用，服務會「睡著」。下一個使用者要等大約一分鐘才會醒過來。這段從睡著到醒過來要等的時間，叫冷啟動（Cold Start）。

解法：用 cron job（定時自動執行的小工作）每 10 分鐘 ping 一次你的服務，讓它一直醒著。要注意免費方案每個月只有 750 小時的運轉時數：一個服務整個月不睡還夠用，兩個都不睡就會超過，超過後所有免費服務會被停到下個月。這也是我不拿它當起點的原因：純靜態頁面根本沒有睡著這回事。

哪裡有邊界：什麼交給 Claude，什麼你自己確認

這一章的動作，大部分可以放心交給 Claude。但有幾件事，做錯了收不回來，或者是用你的名字、你的錢在做。這幾件要你自己看過才放行。

這一章的動作 放心交給 Claude 你一定要自己確認
整理檔案、寫設定檔 寫 wrangler.jsonc、整理 public 資料夾、改路徑 directory 只指 public，不是整個專案
上傳、重新上線 跑 deploy、看錯誤訊息、修到成功 上線前在本機看過一次；上線後用手機打開

還有一條比較看不見的邊界：Claude 會一直加東西。你只是請它把預約表放上網，它可能順手說「我幫你加一個後端」「我建一張表存預約」。AI 會改會修，但會一直改：前端、後端、加欄位、加表，改到後面纏在一起，誰也動不了。這一章只放頁面。它開始往外加東西的時候，先停下來問它要加什麼、加在哪一層。

這些判斷，後面五章一章講一塊：

  • 第十三章 架構拓樸：先畫出整個東西有哪幾塊、怎麼連，才知道它加的東西放在哪
  • 第十四章 功能怎麼切：一塊只做一件事，改一個地方不會牽動全部
  • 第十五章 資料表與欄位：資料的家要先蓋好，不要讓它一直加欄位
  • 第十六章 前後端邊界：什麼可以放在頁面上，什麼（例如金鑰）一定要放後面
  • 第十七章 會出事的地方：兩條上線路線各改各的，就是這一章講的單一資料來源問題
