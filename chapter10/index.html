第十章

Claude Code 怎麼用

一般 LLM 是只能出嘴巴的顧問，Claude Code 是有手有腳能實際動工的工人。這一章從安裝帶你用到順手，也教你替它畫線：哪些事直接做、哪些先問你、哪些碰都不能碰。

前面三章講的是把東西放上網、幫它取個網址、替它找地方存資料。這些事，實際動手的多半是 Claude Code。這一章把它本身講清楚：它跟網頁上聊天的 AI 差在哪、怎麼裝、怎麼下第一句話、怎麼管住它。

會動手，就要先講好它能動到哪裡。這本書一直說「知道邊界」，在這一章，邊界很具體：哪些事它可以直接做、哪些要先問你、哪些碰都不能碰。這些線都是你畫的，後面的權限模式、CLAUDE.md、Hook 就是畫線的工具。

Claude Code vs 一般 LLM（ChatGPT／Gemini 網頁版）

你在 ChatGPT 或 Gemini 的網頁上問問題，它會給你很好的答案、甚至幫你寫一段程式碼。但有個致命的問題：它只能用嘴巴。

它可以告訴你「你應該在 index.html 的第 37 行加一段程式碼」，但它不能幫你開檔案、不能幫你存檔、不能幫你跑指令。你還是得自己動手。

白話比喻：

一般 LLM（ChatGPT／Gemini 網頁版）＝只能用嘴巴的顧問
他坐在旁邊給你建議，但不能碰你的電腦。你問他「這個 bug 怎麼修？」他會說「你去那個檔案改第 37 行」，但他自己不能改。

Claude Code ＝有手有腳的工人
他可以直接打開你的檔案、改程式碼、存檔、跑測試、甚至幫你把東西上傳到網路上。你只需要下指令，他就去做。
一般 LLM（只能出嘴巴）
你：「幫我把首頁標題改成紅色」

AI：「請在 styles.css 裡找到 .title，
加上 color: red;」

然後你要自己：
1. 打開 styles.css
2. 找到 .title
3. 加上那行程式碼
4. 存檔
5. 重新整理瀏覽器確認

你還是得自己動手
Claude Code（直接動手做）
你：「幫我把首頁標題改成紅色」

Claude Code：
1. 自己打開 styles.css
2. 找到 .title
3. 加上 color: red;
4. 存檔
5. 告訴你改了哪一行

你講要什麼，它去做，你驗收

簡單來說，一般 LLM 是你的「軍師」，Claude Code 是你的「施工隊」。軍師能出好主意，但施工隊能直接把房子蓋起來。

Claude Code 的核心差異：控制面向

Claude Code 厲害的地方，不只是「能動手」，更是「你可以精準控制它能做什麼」。就像你雇了一個工人，你可以規定他能進哪些房間、能碰哪些東西。

面向 說明 白話
電腦權限 可以讀寫檔案、執行終端機指令、操作瀏覽器、管理 Git 版控 有手有腳的工人，能搬磚、釘釘子、刷油漆
控制程度 透過 CLAUDE.md 交代規矩、權限模式決定問不問你、權限規則和 Hook 擋住不准做的事 你可以設定這個工人「能做什麼、不能做什麼」，就像給員工一本規範手冊
重點
Claude Code 不是「失控的 AI 自己亂做事」。它更像是一個聽話的員工：你給規範，它就照規範做；你說不能碰的東西，它就不碰。

不過要分清楚「交代」和「上鎖」：寫在 CLAUDE.md 裡的規範是交代，它會盡量照做，但不是硬性的鎖。真的絕對不准碰的事，要用權限規則或 Hook 來擋，那才是鎖。

使用 Claude Code 的方式（不只三種）

Claude Code 不是只有一種打開方式。現在的入口有：終端機裡的 CLI、VS Code、JetBrains、桌面 App、網頁版，再加上手機 App。背後是同一顆引擎，差別只在你從哪裡跟它說話。這一章講的權限模式、CLAUDE.md，在每個入口都一樣適用。下面先講常用的幾條路，其餘的整理在後面的表裡。

1. 終端機裡的 CLI

先分清楚兩個詞。終端機（Terminal）是打字下指令的那個視窗。CLI（Command Line Interface）是在終端機裡用打字操作的工具：claude 是 CLI，後面幾章會出現的 gh（GitHub 的）、wrangler（Cloudflare 的）也都是 CLI。

用法就是打開終端機，打 claude，按 Enter，開始對話：

$ claude
> 幫我看一下這個專案的結構

Claude Code 會直接讀取你的檔案，然後回答你
白話：像直接跟工人面對面說話。沒有花俏的介面，你說一句，他就去做。

這是功能最完整的入口，也是這本指南主要在用的方式。從安裝到做完第一個任務，下面有一整節帶你走：CLI 怎麼用。

2. VS Code 編輯器

如果你用 VS Code 寫程式（或看程式碼），有兩種方式使用 Claude Code：

  • 在 VS Code 內建的終端機裡用：跟上面終端機的用法一模一樣，只是終端機嵌在編輯器裡面
  • 用 Claude Code 擴充功能（Extension）：會出現一個對話面板，像在 VS Code 裡面開了一個 LINE 聊天室
小知識
用擴充功能的好處是，你可以一邊看程式碼、一邊跟 Claude Code 聊天，它改了什麼你馬上在編輯器裡就看得到。

看它改了什麼：Diff

Diff 就是「比較兩個版本的差異」。你可以把它想成 Word 的「追蹤修訂」功能：紅色是刪除的部分、綠色是新增的部分。

VS Code 會在側邊欄列出哪些檔案被改了，點進去就能看到每一行的差異；桌面 App 也有同樣的改動檢視。這是用 Claude Code 很大的好處之一：它改了什麼，你一目瞭然。不用擔心 Claude 偷偷改了什麼你不知道的東西。

白話：Diff 就像老師用紅筆批改作業：哪裡被劃掉、哪裡是新寫的，全部清清楚楚。你不用逐行去比對「到底改了什麼」，工具幫你標好了。

3. Claude Desktop（桌面應用程式）

Anthropic 出的桌面 App。打開後點側邊欄上方的 Code 分頁，就是 Claude Code。App 已經內建，不用另外安裝 CLI，不想碰終端機的人從這裡開始比較順。幾個在這裡用起來特別方便的能力：

  • Computer Use（電腦操控）：可以操控你電腦上的桌面軟體，像是打開沒有 CLI、也沒有網頁版的那種軟體，幫你點按鈕、填資料。就像你的手被 AI 附身了。瀏覽器它只能看、不能點，網頁上的操作要交給 Claude in Chrome（後面讓 Claude 操作畫面那一節有講）。目前是研究預覽版（macOS 與 Windows），預設關閉，要先到設定裡打開
  • Browser 面板：App 內建一個瀏覽器，讓它開網頁、看畫面。跟你平常用的瀏覽器分開，沒有你存的登入
  • Dispatch（用手機派工）：人在外面，用手機 Claude App 丟一個任務回來，由你電腦上的桌面 App 接手去做（電腦要開著），做完或需要你同意時手機會跳通知。手機和桌面 App 要先配對一次；限 Pro、Max、Ultra 方案
  • Schedule 功能（排程任務）：可以設定排程，讓 Claude 在特定時間自動執行任務。例如「每天早上 9 點幫我整理 Email 摘要」。排在自己電腦上的任務，要 App 開著、電腦醒著才會跑；排在雲端的任務，電腦關機也會跑

4. 網頁版與手機 App

在瀏覽器打開 claude.ai/code，或用手機 Claude App 裡的 Code 分頁，Claude Code 會在雲端的機器上跑：不用安裝，筆電闔上它也繼續做。差別是它在雲端，處理的是放在 GitHub 上（或你上傳上去）的專案，不會直接動你電腦裡的資料夾。要處理自己電腦上的資料夾，還是得用 CLI 或桌面 App。

另外有一個叫 Remote Control 的功能：電腦上正在跑的那一場對話，可以用手機或另一台電腦的瀏覽器接著操作，實際做事的還是你那台電腦，所以電腦要開著。

使用方式 介面 適合誰 特色
終端機裡的 CLI 純文字，全用打字 習慣終端機的人，或願意花十分鐘學的人 功能最完整，這本書主要用它
VS Code 終端機或對話面板 有在寫程式／看程式碼的人 邊看程式碼邊對話，改了什麼直接看得到
JetBrains IDE 裡的外掛（要另外裝 CLI） 用 IntelliJ、PyCharm、WebStorm 的工程師 在 IDE 裡看 Diff
Claude Desktop 圖形化桌面 App 的 Code 分頁 不想碰終端機的人 Computer Use、Browser 面板、Dispatch、排程
網頁版／手機 App 瀏覽器或手機 想丟一個長任務、人不在電腦前的人 在雲端跑，不用安裝；處理 GitHub 上的專案

除了這些，還有 Slack、Chrome 擴充功能、GitHub Actions 等整合，屬於進階用法，這裡先不展開。

CLI 怎麼用

簡單說，你在電腦上的工作，幾乎 99% 都可以丟給它自己處理。

這不是哪份報告的統計數字，是我自己每天用下來的體感：只要一件事是「坐在電腦前、動鍵盤滑鼠就做得完」的，大多可以改成跟它講清楚要什麼，它自己做完，你來驗收。

丟給它的是動手。做到哪裡為止、哪裡不准碰，還是你定。

它最擅長的是寫程式，但只要是在終端機裡打指令做得完的事，它都幫得上忙：寫文件、找檔案、查資料。而「打指令做得完的事」，比多數人以為的多很多。

非工程師實際會丟給它的工作

工作 你說什麼 它會自己做哪些步驟
整理資料夾與檔名 「把這個資料夾裡的檔案依類型分到子資料夾，檔名前面加上日期。先列出你打算怎麼分，我說好再動。」 列出所有檔案 → 提分類方案等你點頭 → 建資料夾、搬檔、改名 → 再列一次，核對數量有沒有少
處理 Excel 「把這三個月的訂單 Excel 合成一份，算出每個客戶的總金額，另存成新檔，原檔不要動。」 寫一小段程式去讀 Excel → 合併、計算 → 另存新檔 → 抽幾筆回頭對照原檔驗算
處理 PDF 「讀這個資料夾裡的合約 PDF，把簽約日、到期日、金額整理成一張表。讀不清楚的標出來，不要猜。」 逐份讀 PDF → 抽出欄位 → 寫成表格檔 → 列出需要你人工確認的幾份
批次改圖 「把 photos 裡的圖全部縮到寬 1200 像素、轉成 JPG，放到新資料夾 resized，原圖留著。」 看電腦裡有沒有能用的改圖工具，沒有就提議安裝 → 寫批次指令 → 執行 → 抽查幾張的尺寸和格式
寫信草稿 「依這份報價單寫一封給 B 咖啡店的說明信，語氣客氣、三段以內，存成草稿檔，不要寄出。」 讀報價單 → 寫草稿存成文字檔 → 跟你說重點放在哪。要它真的寄信，得先幫它接上信箱（靠下面會講的 MCP）
查資料整理成報告 「查三家同類服務的方案與價格，整理成一頁比較表，每一項附官方網址。查不到的寫『查不到』，不要猜。」 上網搜尋 → 打開各家的網站讀 → 整理成檔案 → 每一項附上來源網址
架網站並部署 「幫 A 設計工作室做一頁式介紹網站，要有營業時間和地圖連結。做好先在我電腦上開給我看，我說好再上線。」 寫網頁檔案 → 在你電腦上開起來給你看 → 照你的意見改 → 用部署工具的指令上線（怎麼部署看第七章）
做影片 「用這五張產品照做一支 30 秒的直式介紹影片，每張照片配一句字卡。」 用 Remotion 這類「用程式做影片」的工具開專案 → 一幕一幕寫 → 先輸出畫面給你看 → 照意見修改 → 輸出成影片檔（Remotion 在第十八章細講）

「它會自己做」那一欄是示意，實際步驟它會看你的檔案狀況自己調整。重點在「你說什麼」那一欄：每一句都講了要什麼結果，多半還講了哪一步先停下來或什麼不能動。這就是第三章說的「目標」和「邊界」。

「自主處理」是什麼意思

你給的是目標，不是步驟。它自己拆步驟、動手、檢查，出錯自己修，一直到做完、或真的卡住了才回來找你。過程分三段：看現況、動手做、檢查結果。三段會反覆轉，直到任務完成，而且你隨時可以插手。

你給目標要什麼、怎樣算完
它自己反覆轉，直到做完
看現況讀檔案、查資料
動手做改檔案、跑指令
檢查結果沒過就回頭再修
你驗收看結果、看改動

舉個不寫程式的例子（示意，實際每次不一樣）：

你：「把這個資料夾的 200 張照片，依拍攝日期改檔名。做完總數要一樣。」

它自己做的事：
1. 列出資料夾，確認真的有 200 張
2. 寫一小段程式，讀每張照片的拍攝日期
3. 先拿 5 張試改，看結果對不對
4. 全部改完，再數一次：200 張都在
5. 發現有 3 張沒有日期資訊，沒有硬改，列出來問你怎麼處理

第 3 到 5 步就是「自主」的重點：它會自己驗算，出錯自己修，判斷不了才停下來問。

你能幫的最大的忙
給它一個「怎樣算做完」的標準，讓它有東西可以自己對答案。例如「做完檔案總數要一樣」「金額加總要等於原表的合計」。有標準，它才知道什麼時候該回頭再修。

它會先停下來問你的事

「自主」不等於「什麼都不問」。它問不問，看的是當下的權限模式（四種模式的對照和切換方法在下面的步驟 6）：

情況 它會怎麼做
手動模式（Manual） 讀檔案不問；每次要改檔案、跑指令之前，都會停下來等你同意。
自動模式（Auto） 不再一步一步問。讀檔、改工作資料夾裡的檔案，直接做，不經過審查。其餘的動作（主要是跑指令、連到外面的服務）先交給另一個專門把關的模型看過，有風險就攔下來。預設會攔的例子：從網路下載程式就直接執行、把機密資料送到外部、正式環境的部署、永久刪除這場對話開始前就存在的檔案。
任何模式 像「把你整個使用者資料夾刪掉」這種對重要位置的刪除，不會自動放行，一定停下來問你。另外，它主動問你的問題，一定等你回答；但自動模式下它比較少問，會傾向一路做下去。
操作瀏覽器時 碰到登入頁或「我不是機器人」驗證，它會停下來，請你自己處理。

在自動模式被攔下來時，畫面會跳通知。想知道攔了什麼，打 /permissions，切到「Recently blocked」分頁就看得到，確認沒問題再放行。連續被攔 3 次、或一場裡累計被攔 20 次，自動模式會先暫停，退回一步一步問你。

付款、寄信、發訊息：你要自己先畫線
預設的攔截清單管的是「機密資料外流」「救不回來的刪除」這一類，沒有保證「每一筆付款、每一封信寄出前一定先問你」。所以我的做法是在指令裡直接講：「寄出前先給我看」「付款那一步停下來等我」「刪除前先列清單」。

你講過的界線（例如「先不要上傳」「上線前等我看過」），自動模式會照著攔，要你開口才算解除。它自己覺得「條件達成了」不算。

但這些界線是從對話裡讀的，不是存成規則。對話太長、前面被壓成摘要之後，界線可能跟著不見。長任務做到一半，重要的界線再講一次；要永久有效，就用 /permissions 寫成禁止的規則。

第一次用，為什麼要看它做了什麼

  • 它聽懂的，不一定是你想的。「整理一下」對你是分資料夾，對它可能是連檔名一起改。看過一次，你就知道下次要怎麼講
  • 不是每件事都能復原。按兩下 Esc 可以把它改過的檔案倒回去，但只限它用內建的編輯功能改的檔案；用指令搬走、改名、刪掉的檔案不一定救得回來，寄出去的信、上線的網站、寫進資料庫的資料更是倒不回來
  • 自動模式不保證安全。它只是少問你幾次。方向你有把握的事才放手，敏感的事還是要自己看
第一次的安全做法
  1. 先把資料夾複製一份，讓它在副本上做
  2. 第一句先叫它「只看不改」，或按幾下 Shift + Tab 切到 Plan 模式，讓它先交計畫，你同意才動手（Plan 模式怎麼用，第四章有完整流程）
  3. 做完叫它列出「你改了哪些檔案、各改了什麼」
  4. 想看它實際跑了哪些動作，按 Ctrl + O 展開詳細紀錄

步驟 1

Yes：只同意這一次，下次同類的動作還會再問。最保險，剛開始用建議都選這個。

Yes, and don't ask again：同意，而且以後同一類指令不再問。跑指令的同意會存成規則，之後在這個專案裡都有效；改檔案的同意則只到這一場結束。確定是無害的例行動作再選。

Yes, and switch to auto mode：同意，並把這一場切成自動模式。之後不再一步一步問，有風險的動作改由背後把關的模型攔。這個選項不是每次都會出現。

No：不同意。它不會執行，停下來等你說接下來怎麼做，按 Esc 效果一樣。想順便告訴它為什麼，先移到 No 再按 Tab，可以補一句話，它會照你的理由調整後繼續。

核心功能介紹

Claude Code 不只是「能幫你改檔案的 ChatGPT」。它有一整套工具和機制，讓你能像管理一個團隊一樣管理 AI。以下是你一定會碰到的核心功能。名字很多，先知道各自是什麼；要用的時候跟 Claude 說你要什麼，設定檔讓它寫。

CLAUDE.md：員工的 SOP 手冊

每次開新對話，它都是從頭開始。要它記得你的規矩，就寫進 CLAUDE.md：放在專案資料夾最上層的純文字檔案。Claude Code 每次啟動時都會先讀它，就像員工每天上班前先看一次規範手冊。

你可以在裡面寫：

  • 這個專案用什麼技術、放在哪裡
  • 程式碼風格（例如：用 2 個空格縮排，不要用 Tab）
  • 哪些檔案不能動
  • 特殊的工作流程（例如：改完先開給我看，我說好再上線）
# CLAUDE.md 範例

## 專案規範
- 純靜態網站：HTML、CSS、JavaScript，不用打包
- 放在 Cloudflare，資料庫用 Supabase
- 縮排用 2 個空格
- 改完先在我電腦上開起來給我看，我說好再上線

## 禁止事項
- 不要動 database/ 資料夾
- 不要在程式碼裡寫入任何密碼或 API Key

不會寫就打 /init，它會看過資料夾幫你產生初稿，你再改。裡面該寫哪些邊界，第三章有講。

CLAUDE.md 放在哪一層

CLAUDE.md 其實不只一個。最常用到的是前兩層，就像公司的規範有分「全公司通用」和「各部門專用」：

層級 位置 作用 比喻
全域（你個人的） ~/.claude/CLAUDE.md 你所有的專案都會讀到。放通用偏好：用繁體中文回我、先講結論 公司的「員工守則」，不管你調到哪個部門都要遵守
專案 專案資料夾裡的 CLAUDE.md 只有這個專案會讀到，跟團隊共用。放技術棧、命名、部署規則 部門的「SOP」，只有這個部門的人要看
專案裡只給自己的 專案資料夾裡的 CLAUDE.local.md 只有你讀得到，不進版控、不跟團隊共用 你自己貼在螢幕邊的便利貼

Claude 每次開工，這幾份都會讀進去，是「疊在一起讀」，不是誰蓋掉誰，所以不要寫互相矛盾的規則。另外，公司 IT 可以統一派發一份全公司共用的組織層級規範。

Memory：跨 Session 記憶系統

一般的 LLM 對話，關掉視窗就全忘了。Claude Code 有記憶系統，可以把重要的事情記住，下次開新的 Session 還是知道。

Memory 的運作方式
Claude Code 有兩套記憶。一套是你寫的 CLAUDE.md；另一套是它自己記的「自動記憶」（auto memory）：工作中它會把你的偏好、你糾正過它的事記成筆記檔，存在你的電腦上，預設就是開的。下次你再開對話，兩套都會先讀進來，就像員工翻看自己上次的工作筆記。

你說「記住這件事」，它會寫進自動記憶；想寫進 CLAUDE.md，就明講「把這條加進 CLAUDE.md」。想看它記了什麼，打 /memory。
交代不是上鎖
官方寫明：CLAUDE.md 和記憶對它來說是參考，不是強制設定。它會盡量照做，但不保證。真的絕對不准碰的事，要用權限規則（/permissions 裡設成禁止）或下面的 Hook 來擋，那才是鎖。

Subagent：帶一個團隊做事

Claude Code 不只是一個人。它可以「派出」子代理人（Subagent），讓多個任務同時進行。就像工頭把工作分給不同工人平行處理：

  • Subagent A：去查這個 API 的文件
  • Subagent B：同時幫我改首頁的 CSS
  • Subagent C：同時去跑測試

三個任務同時進行，比一個一個排隊做快很多。每個子代理在自己的對話空間做事，做完只把摘要交回來，所以要翻一大堆檔案、但你只要結論的時候特別好用，主對話不會被塞滿。用量算在同一個額度裡。

Hook：自動化觸發器

Hook 是一種「自動觸發的規則」：在固定時機一定會跑的小程式，不靠它記得，時間到就跑。你可以設定：

  • 每次 Claude Code 要修改檔案之前，先檢查是不是你說不准動的檔案
  • 每次 Git commit 之前，先跑測試
  • 每次部署之前，先做安全檢查
  • 它改完檔案就自動排版；它在等你回覆時，跳一個桌面通知

打 /hooks 看已經設了哪些。

白話：Hook 就像你在工地門口貼的告示牌：「進門前先戴安全帽」。不管誰進來，都會先做那件事。

Plugin／Skill：可安裝的擴充包

你可以幫 Claude Code 安裝各種「技能包」，讓它會做更多事情。例如：

  • Skill：一套預先寫好的指令和規範，是一個資料夾，主檔叫 SKILL.md。平時只掛一行說明，用到才把內容讀進來；打 /技能名 叫它，或它判斷用得上時自己拿出來用。例如「程式碼審查 Skill」會讓 Claude Code 用特定的標準幫你檢查程式碼品質。同一套交代你已經貼了第三次，就該寫成 Skill
  • Plugin：外掛模組，把 Skill、Subagent、Hook、MCP 打包成一包，一次裝好，可以擴充 Claude Code 的能力。例如 Discord Plugin 讓它可以讀寫 Discord 訊息。打 /plugin 從清單挑

就像買一整組別人配好的工具箱，不用一件一件挑。

名稱 一句話 什麼時候用
CLAUDE.md 員工守則，每次開工先讀 專案的技術、規矩、不准碰的地方

MD 檔的重要性

Markdown 是什麼？

Markdown（簡稱 MD）是一種用純文字寫格式的方法。你可以把它想成「簡化版的 Word」。

在 Word 裡面，你要粗體就用滑鼠選取文字然後點 B。在 Markdown 裡面，你只要打：

**這段文字會變粗體**

# 這是大標題
## 這是次標題

- 這是項目符號
- 第二點

`這是程式碼`

就這麼簡單。不需要任何特殊軟體，用記事本就能寫。CLAUDE.md、SKILL.md 都是這種格式。

為什麼 Claude Code 生態都用 MD？

有三個關鍵原因：

  1. 省 Token：純文字檔案不含格式代碼，同樣的內容，MD 檔通常比 Word 檔小很多。檔案越小，AI 讀得越快、花的 Token 越少
  2. 好讀：不管是人還是 AI，讀純文字都很直接。不像 Word 或 PDF，裡面一堆格式代碼會干擾 AI 的理解
  3. Git 友好：Git 版控系統是用「逐行比較」來追蹤變更。純文字的 MD 檔可以精準看出哪一行被改了；Word 檔是二進位格式，Git 存得下來，但看不出改了哪一行

MCP：Claude Code 的「手臂」

MCP 是什麼？

MCP（Model Context Protocol）是一種通訊協議，讓 Claude Code 可以接上外部服務。你可以想像成：Claude Code 本身是一個人，MCP 就是它多伸出去的手臂，每一隻手臂握住一個外部服務。有些介面把它叫「連接器」（Connectors），是同一種東西。

沒有 MCP 的 Claude Code：讀寫你電腦上的檔案、跑終端機指令、上網查資料。

有了 MCP 的 Claude Code：還能直接連上資料庫、GitHub、瀏覽器、信箱、行事曆這些外部服務，幫你查、幫你改。

比喻：手機本身 vs 手機上的 App。

手機出廠只能打電話、傳簡訊。但你裝了 LINE 就能聊天、裝了 Uber 就能叫車、裝了 Google Maps 就能導航。

MCP 就像 Claude Code 的 App。每接一個 MCP，Claude Code 就多一隻手，能伸進一個外部服務去查、去改。

常用 MCP 列表

MCP 能做什麼 你可以這樣說 有沒有官方 CLI
Supabase 操作資料庫、讀寫資料表 「幫我查所有 VIP 客戶」（幫你開抽屜、找資料） 有：supabase
GitHub 管理原始碼、發 PR、查 Issue 「幫我開一個 PR」「合併這個分支」 有：gh
Cloudflare 部署網站、管理 DNS 「幫我把這個網站上線」 有：wrangler
Google Cloud 管理雲端服務 「幫我開一台 VM」「查一下 log」 有：gcloud
Chrome DevTools 操控瀏覽器、讀網頁的錯誤訊息 「幫我打開這個網頁，看看有沒有 bug」 沒有，用 MCP（下面實戰組合那一節細講）
Gmail 找信、讀信、寫草稿 「幫我找最近客戶寄來的信」 沒有，用 MCP
Google 行事曆 讀寫行事曆 「幫我查下週二有什麼會議」 沒有，用 MCP
Brave Search 換一家搜尋引擎 Claude Code 本身就會上網搜尋，「幫我查這個技術的最新文件」直接說就行。想改用 Brave 的搜尋結果才需要裝，而且要先申請 Brave 的 API key 平常用不到
不用一次全裝
MCP 是「需要什麼裝什麼」。剛開始一個都不裝也行：GitHub、部署這些有官方 CLI 的，先用 CLI 就好（看下一個框）。等到要接信箱、行事曆這類服務，再一個一個加。
先看有沒有 CLI，再裝 MCP
表裡前四個服務本來就有自己的官方 CLI：Supabase 是 supabase、GitHub 是 gh、Cloudflare 是 wrangler、Google Cloud 是 gcloud。Claude Code 本來就會打指令，裝好 CLI、登入一次，不裝 MCP 也能開 PR、部署網站、改資料庫。這幾個 CLI 的用法和為什麼比較划算，在第十一章。

所以我的順序是：有官方 CLI 的先用 CLI；沒有 CLI 才裝 MCP（連接器），像信箱、行事曆；要操作網頁，交給瀏覽器工具；都不行，才用 Computer Use（讓它看著螢幕動滑鼠，下一節）。

跟 Claude 這樣說就好：「這件事有官方 CLI 的話用 CLI 做，沒有再用 MCP。」
Gmail、Google 行事曆怎麼接
這兩個不用在電腦上裝東西。到 claude.ai 的「連接器」（Connectors）設定頁把 Gmail、Google Calendar 連起來、完成授權；之後只要 Claude Code 是用同一個 claude.ai 訂閱帳號登入的（不是用 API key），它們就會自動出現。在 Claude Code 裡打 /mcp 可以看到目前接了哪些。

接任何 MCP 之前，先確認來源可信。會去外面抓內容的 MCP，抓回來的文字可能夾帶想騙 AI 的指令，官方文件也特別提醒這一點。

延伸：讓 Claude 操作畫面

CLI 很省 Token，那讓 Claude 直接操作畫面就不能用嗎？不是，它有適合的場景。只是指令和 MCP 都碰不到的，才輪到它看著畫面操作。現在有三種做法，由輕到重：

做法 Claude 操作的是 怎麼開
Claude in Chrome 你自己的 Chrome 或 Edge（其他 Chromium 系的瀏覽器也行），沿用你已經登入的網站 裝同名的瀏覽器擴充功能，再用 claude --chrome 啟動。要付費方案，而且 Claude Code 要用 claude.ai 帳號登入
桌面 App 的 Browser 面板 App 內建的瀏覽器，跟你平常的瀏覽器分開，沒有你存的登入 在桌面 App 的對話標題列點 Browser
Computer Use 整個桌面：開軟體、移滑鼠、點擊、打字 預設關閉。桌面 App 到設定裡打開（macOS、Windows）；CLI 只有 macOS，在 /mcp 裡把 computer-use 打開

Computer Use 還在研究預覽階段，只開放 Pro、Max、Ultra 個人方案，每個軟體第一次要用時都要你當場同意。它適合的是沒有 CLI、也沒有網頁版的桌面軟體。瀏覽器它只能看、不能點，網頁上的操作要交給 Claude in Chrome。

能用指令或連接器做的，Claude 就不看畫面。Computer Use 排最後，官方文件直說它是幾種做法裡涵蓋最廣、也最慢的一種。

適合操作畫面
- 沒有 CLI、沒有 API 的網站
（某些政府網站、廠商後台）
- 只做一次的帳號設定、填表單
- 看一眼網頁有沒有跑版
- 把操作過程錄成 GIF 當教學
不適合操作畫面
- 每天重複的操作
（用 CLI 取代）
- 大量資料處理
（用 API 取代）
- 部署和版控
（用 wrangler、gh 取代）
它用的是你的身分
Claude in Chrome 沿用你已經登入的帳號，網頁上的文字也可能夾帶想騙 Claude 的指令，官方說明也寫明這項功能仍有風險。碰到登入頁或「我不是機器人」驗證，它會停下來請你自己處理。付款、轉帳、刪資料這類不能反悔的動作，自己動手。
總結
有官方 CLI 的先用 CLI（省 Token、快、穩定）。沒有 CLI 才裝 MCP（連接器）。要操作網頁，交給瀏覽器工具。都不行才用 Computer Use。

實戰組合：Chrome DevTools + Claude Code

Chrome DevTools 就是在 Chrome 按 F12 打開的「開發者工具」，可以看 DOM（網頁結構）和 JS（JavaScript）程式跑得怎樣。Chrome 開發者工具團隊出了一個 Chrome DevTools MCP，讓 Claude 直接讀這些資料。這比你手動從開發者工具複製訊息給 AI 快很多。

什麼是 JS？
JS（JavaScript）是讓網頁「會動」的程式語言。按鈕點了會跑出東西、表單可以送出、動畫會播放，這些都是 JS 在背後做的事。

Claude 搭配 DevTools MCP 可以直接讀取：

  • Console 錯誤訊息：不用你複製貼上，Claude 自己去看
  • Network 請求：API 有沒有回應、回了什麼資料
  • DOM 結構：元素的 class、id、屬性，全部一覽無遺
手動方式（慢又容易漏）
1. 你打開 F12 開發者工具
2. 看到紅色錯誤訊息
3. 截圖或複製錯誤訊息
4. 貼給 Claude
5. Claude 問你更多問題
6. 你再去 F12 查更多資料
7. 來回好幾次才找到問題

你變成 AI 和瀏覽器之間的「傳話人」
DevTools MCP（快又完整）
1. Claude 直接讀 Console 錯誤
2. Claude 直接看 Network 請求
3. Claude 直接分析 DOM 結構
4. 一次找到問題根源
5. 直接修改程式碼

Claude 自己去看、自己去查、自己修
官方也有自己的 Chrome 整合
除了 DevTools MCP，Claude Code 現在可以搭配上一節講的 Claude in Chrome：它在你的 Chrome 裡開分頁，直接讀 Console 錯誤和 DOM 狀態，再回頭改程式。它用的是你瀏覽器現有的登入狀態；碰到登入頁或 CAPTCHA（「我不是機器人」驗證）會停下來，請你自己處理。

補充一點：有時候 Headless Browser（無頭瀏覽器，就是沒有畫面的自動化瀏覽器，像 Playwright）會遇到問題，通常是因為取得的資訊不夠完整，或是 DOM 沒有全部渲染完。在做 E2E 測試（End-to-End，從頭到尾的完整流程測試）的問題排除時，DevTools 加 Claude 是很快的組合。

補充術語
  • TDD（Test-Driven Development，測試驅動開發）：先寫測試，再寫功能。確保每個功能都有測試保護。
  • E2E（End-to-End Testing，端對端測試）：模擬真實使用者操作整個流程（打開網頁 → 點按鈕 → 填表單 → 送出），確認一切正常。
  • 這些概念在你的專案變大的時候會越來越重要。現在先知道名字就好。

Claude Code Quickstart 懶人包

如果你覺得上面這些東西要一個一個設定太麻煩，我另外整理過一個懶人包，讓 Claude 照著一份設定說明，把常用的 MCP 和技能包一次裝好。

github.com/lgscvb/claude-code-quickstart

這個 Quickstart 懶人包包含：

- 幾個常用 MCP 的設定範本（Chrome DevTools、Supabase、Google Cloud、Cloudflare、GitHub、Remotion）
- 一組精選的 Skills（讓 Claude Code 照固定做法做事的技能包）
- CLAUDE.md 是什麼、模式怎麼切的白話說明
- 適合完全新手的安裝流程，從 VS Code 開始，不用碰終端機

流程是：裝 VS Code 和 Claude Code 擴充功能 → 開一個工作資料夾 → 把 README 裡那段話貼給 Claude，它照設定說明自己裝。

如果你身邊有朋友想開始用 Claude Code，把這個連結丟給他就好。不用解釋太多，照著 README 走一次就能開始用。

安裝步驟（極簡版）
1. 裝好 VS Code，在擴充功能裡搜尋 Claude Code，裝 Anthropic 官方那一個，登入你的帳號
2. 在桌面開一個新資料夾（取英文名字），拖進 VS Code
3. 打開 Claude Code 的對話面板，把 README「第四關」那一整段話複製貼上，按 Enter
4. 它要你同意權限時看一下在做什麼；瀏覽器跳出登入頁時，自己登入、按同意
5. 跑完打 /mcp，確認接上了哪些
用之前知道兩件事
  • 裡面的 MCP 設定是範本。照這章的順序挑需要的開：有官方 CLI 的先用 CLI，不用全裝
  • README 裡教的「跳過所有權限詢問」那個設定（Allow Dangerously Skip Permissions）先不要開，理由跟上面「不要照抄的指令」一樣

這章帶走什麼

  • Claude Code 是會動手的 AI。電腦上的工作，幾乎都能交給它做；做到哪裡為止、哪裡不准碰，你定。
  • 給它目標和「怎樣算做完」，不是一步一步的指示。重要的停止點寫在指令裡。
  • 權限模式決定它問不問你。終端機裡預設是 Auto，會攔高風險動作，但寄信、付款這類要你自己先講。第一次用，先在副本上做、先叫它只看不改。
  • CLAUDE.md 和記憶是交代，權限規則和 Hook 才是鎖。
  • 工具先後：官方 CLI → MCP → 瀏覽器工具 → Computer Use。MCP 需要什麼裝什麼。

這章的邊界畫在「它能動你電腦上的什麼」。下一章往外一層：你要它做出來的東西，用什麼材料蓋，才改得動、修得了。

跟 Claude 怎麼說

「先不要改任何東西，看完這個資料夾，跟我說你打算怎麼做。」

「做完告訴我改了哪些檔案、各改了什麼。總數要跟原本一樣。」

「寄出、付款、刪除、上線之前，一律先停下來等我說好。」

「這件事有官方 CLI 的話用 CLI 做，沒有再用 MCP。」

「把『上線前先給我看』這條加進 CLAUDE.md。」

「剛剛那一行指令在做什麼？會動到哪些檔案？講清楚再跑。」
