第十一章

技術棧：不打包，先找 GitHub

上一章，Claude Code 開始替你動手。這一章講它動手時用什麼材料：蓋房子之前，你得知道要用鋼筋還是木頭。材料選得簡單，你才看得懂它做了什麼，也才看得出哪裡能動、哪裡不能動。

技術棧就是做一個東西用到的整套材料：頁面用什麼寫、放在哪裡、資料存在哪、程式碼怎麼留版本。第七章到第九章你已經照著把網站放上去、接好網域、開了資料庫，這一章退一步講：為什麼是這幾樣，換別的會怎樣。

這件事你不講，Claude 會自己選。它常選工程師團隊那一套，做得出來，但你看不懂、改不動，等於把邊界整個交出去。第一章說過，能改能修靠的是知道邊界。材料選對，邊界才看得見。

我的立場就兩句：動手前，先上 GitHub 找有沒有現成的；頁面不打包，改完直接上傳。下面一樣一樣講。

選擇原則

市面上的工具和服務多到眼花撩亂。身為一個想用 Claude Code 做事的非工程師，你不需要每個都懂，但你需要知道怎麼選。四個原則：

  1. 先找現成的
    你想做的東西，很可能已經有人做好、公開放在 GitHub 上。動手前先找，做法在下面。
  2. 有 CLI 優先
    終端機是打字下指令的那個視窗；CLI 是在終端機裡用打字操作的工具，claude、gh、wrangler 都是 CLI。服務有 CLI，Claude Code 就能直接下指令操作，不用截圖找按鈕。後面會解釋為什麼這很省 Token。
  3. API 好接、省 Token
    好的 API＝一行指令就能拿到資料。不好的 API＝要寫一大堆程式碼才能拿到同樣的東西。Claude Code 多寫一行程式碼，就多花一點 Token。API 是什麼，下一章細講。
  4. 免費額度夠用
    初期的個人專案，免費額度通常就夠了。等真的有流量再升級，不要一開始就花錢。
重點
你不是在選「功能最多的工具」，是在選「跟 Claude Code 配合得好、你自己也看得懂的工具」。一個有 CLI、有好 API、有免費額度的工具，比一個功能強大但只能在網頁上點的工具好用得多。

第一條：動手前，先上 GitHub 找

GitHub 是放程式碼的平台，很多人把自己做的東西公開放在上面。預約、報價單、問卷、會員系統這類常見的東西，常常已經有人做過。先找，比從零做快，別人踩過的坑你也不用再踩一次。

三步：

  1. 搜
    用功能的英文關鍵字，GitHub 上的說明大多是英文。不知道英文怎麼講，請 Claude 幫你想，再讓它用 gh（GitHub 的 CLI）直接搜：
    gh search repos "booking system" --sort stars --limit 10
    自己在 github.com 搜也行，關鍵字後面可以加條件：stars:>100（星星超過 100 個）、pushed:>2026-01-01（2026 年以後有更新）。
  2. 判斷能不能用，看五件事：
    • 最近有沒有更新：停在一兩年前，或標了 Archived（封存），先跳過
    • 星星數和 Fork 數：多少人收藏、多少人複製一份去用。只有個位數的要小心
    • 授權條款（License）：MIT、Apache-2.0 這類可以商用；GPL、AGPL 有附帶條件；沒寫授權的，別人不能拿去複製、改寫
    • 說明文件（README）：有沒有寫清楚怎麼安裝、怎麼用
    • 問題回報（Issues）：一堆人回報、好幾個月沒人理，代表沒人在顧
  3. 找到之後，先讀懂再決定
    請 Claude 把專案讀一遍、用白話講出它分成哪幾塊，再三選一：直接用、改一部分、只借做法。
跟 Claude 怎麼說
「我想做美髮店的線上預約。先不要寫程式，幫我想三組英文關鍵字，用 gh 搜 GitHub，列出前五個專案的星星數、最後更新日期、授權條款。」
「把第二個讀一遍，用白話講它分成哪幾塊、資料存在哪。再建議我直接用、改一部分，還是只借做法。」

什麼需要「一直跑」、什麼不用

選材料之前，先搞懂一個根本問題：你做的東西，需不需要一台一直開著的機器？多數時候，答案是不用。

白話比喻：

為什麼要在意「需不需要機器」
因為這直接影響成本和維護。傳單和門鈴是有人來才算一次，沒人用就不花錢。一直開著的機器按時間計費，沒人用也照算，還得有人盯著它有沒有掛掉。

要不要「打包」：我的答案是先不要

請 Claude 做網站，它常會順手選 React、Vue 或 Next.js。這類做法都要先打包才能上線：把你寫的檔案丟進一套工具，壓成另一批檔案，再把那批放上網。我不推薦。我自己用的是純靜態頁面：HTML、CSS、JS 三種檔案，改完直接上傳。

白話：純靜態頁面＝手寫卡片，寫完就能寄。打包＝送印刷廠：你改的是版型，要等印好才能寄。

不推薦打包，三個理由：

  • 每改一次都要等：改一個字也要重新打包。打包失敗，就上不了線
  • 套件要一直跟著升級：打包那一套靠一大堆別人寫的套件撐著，放著不管，就會冒出安全性問題
  • 上線的東西你看不懂：上線的是機器壓過的檔案。AI 改壞了，你查不出是哪裡。純靜態頁面你存了什麼，上線的就是什麼

第三點最要緊。AI 會改會修，但會一直改，改到後來沒人知道哪裡牽著哪裡。上線的東西你看得懂，才有辦法說「這裡不准動」。

代價也老實講：共用的區塊（例如選單）要每頁各改一次。這個站就是例子：章節和附錄共 20 頁，加上首頁，每一頁各有一份選單。要多放一個章節連結，我是請 Claude 寫一支小程式，一次改完全部，再檢查有沒有漏。

檔案是多，但不用你一頁一頁改，交給 Claude 一次改完。頁數上百了，才值得考慮打包那一套。

什麼時候才值得上打包那一套？頁面上百、好幾個人一起改，或者你身邊已經有工程師。那不是你現在該煩惱的事。

跟 Claude 怎麼說
「用純靜態頁面做：HTML、CSS、JS。不要用 React、Vue、Next.js，不要有打包步驟，改完要能直接上傳。」

我用的組合：Cloudflare、Supabase 或 D1、GitHub

我自己的專案在用的組合：網站做成純靜態頁面放 Cloudflare，資料放 Supabase（資料單純的話用 Cloudflare D1），程式碼放 GitHub。資料庫、會員登入不自己從頭寫。大部分小專案，這三樣就夠了。

1. 網站：純靜態頁面放 Cloudflare

HTML、CSS、JS 放上去就是網站，這個站也是。怎麼一步一步放上去，第七章 部署帶你做過。

  • 新專案用 Workers：Cloudflare 能放網站的服務有 Workers 和 Pages 兩個，官方文件現在寫「新專案從 Workers 開始」。Pages 還能用，舊專案不用急著搬
  • 免費版夠大：靜態檔案被瀏覽不限次數、不計費；一個網站免費版最多放 20,000 個檔案
  • 接上 GitHub 就自動上線：推上去就部署。純靜態頁面沒有打包這一步，不用等
  • 有 CLI wrangler，Claude Code 可以直接下指令部署

2. 資料：Supabase 或 Cloudflare D1

Supabase 是現成的後端服務，底層是 PostgreSQL 資料庫。要會員登入、要存檔案的專案選它：

  • 不用自己寫後端：資料表授權開放之後，它就提供現成的存取窗口（API）。新建的表要先明確授權才會開放，再搭配 RLS，時程和做法見第九章 資料庫
  • 純靜態頁面也接得上：頁面上的 JS 直接連它，做會員登入、後台都不用打包
  • 有 CLI 管資料表的變更：每次改資料表都留一份紀錄，這叫 Migration，等於資料庫結構的版本控制。Claude Code 用 supabase CLI 就能改，不用你去網站上點
  • 免費版的限制先知道：同時最多 2 個專案，一週沒有動靜就會被暫停，要到後台手動恢復。給客人用的正式服務請升級付費方案
白話：Supabase 像一個自帶管理員的檔案櫃。你建好抽屜（資料表），說好這個抽屜可以對外，它就安排一個人坐在旁邊幫你遞資料（API）。你不用自己雇人。沒交代的抽屜，管理員一律不開。
管理員要先交代規矩
把關分兩層。第一層是授權（GRANT）：這張表開不開放給頁面連。新建的表預設不開放，頁面連過去會看到「permission denied for table」，這是正常的，請 Claude 只替要給頁面用的表補上授權。第二層是 RLS（Row Level Security，逐列權限）：每一列資料誰能看、誰能改。規則沒設好，任何打開你網頁的人都可能讀到、改到別人的資料。什麼可以放在頁面上、什麼一定要放在後面，第十六章 前後端邊界會細講。先跟 Claude 說：「每張表都開 RLS，要給頁面用的表才授權，列出每張表誰能讀、誰能寫。」

Cloudflare D1 是 Cloudflare 自己的資料庫（SQLite 語法），一樣用 wrangler 管。資料單純、不需要會員登入時用它，跟網站放同一家，少管一個帳號。兩家怎麼開、怎麼選，第九章 資料庫講過；資料表怎麼設計，兩邊都一樣，見第十五章 資料表與欄位。

3. 版控：GitHub

版控就是存檔加上每一次修改的紀錄，改壞了可以退回去。GitHub 是放這些紀錄的地方（像程式碼的 Google Drive），也是前面自動上線的起點、你找現成專案的地方。

  • 有 gh CLI：Claude Code 可以直接用指令建專案（Repository）、送修改（Pull Request）、管問題回報（Issue）
  • 免費帳號就夠用，公開、私人的專案（repo）都不限數量；私人專案有些進階功能要付費
用途 推薦工具 CLI 免費額度
網站（純靜態頁面） Cloudflare Workers
（舊專案可留在 Pages）		 wrangler 靜態檔案被瀏覽不限次數；後端小程式每天 10 萬次請求
資料庫＋會員登入 Supabase supabase 2 個專案，每個資料庫 500 MB；API 請求不限次；每月 5 萬名活躍使用者；Edge Functions 每月 50 萬次
輕量資料庫 Cloudflare D1 wrangler 每個資料庫 500 MB、整個帳號合計 5 GB、每天 500 萬列讀取
版控 GitHub gh 公開、私人 repo 都不限數量

怎麼選

只是要讓人看的網站？（介紹頁、作品集、活動頁）
→ 純靜態頁面放 Cloudflare。

要存資料？（會員、訂單、表單）
→ 頁面一樣放 Cloudflare，資料放 Supabase；資料單純、不需要會員登入，用 D1。

要定時自動做一件事？（每天早上寄報表、每小時檢查訂單）
→ 不用為了排程開機器。用 Cloudflare Cron Triggers（免費版可設 5 個）或 Supabase Cron。

一定要一台一直開著的機器？
→ 看下一節。

手上已經有一個 Next.js 專案的，可以放 Vercel，它跟 Next.js 是同一家做的。但 Vercel 免費方案只限個人、非商業用途，新專案我不從那裡開始。其他部署服務（Vercel、Netlify、Render、GCP）的比較在第七章 部署。

什麼時候才需要一台自己的機器（GCP VM）

VM 是什麼？

VM（Virtual Machine，虛擬機器）＝在雲端租一台 24 小時開著的電腦。它不在你桌上，但你可以遠端連上去操作，就像遠端遙控一台電腦。

VM 規格的白話翻譯

規格 白話 例子
CPU 腦袋聰不聰明（同時處理幾件事） 1 vCPU＝一次做一件事
4 vCPU＝同時做四件事
RAM（記憶體） 桌子夠不夠大（同時放幾份文件） 1 GB＝小桌子，跑簡單程式
8 GB＝大桌子，跑資料庫沒問題
Disk（硬碟） 儲藏室的容量 10 GB＝放程式碼夠了
100 GB＝可以存大量資料

GCP e2-micro：免費，或每月約 6 美元
場景三：正式產品上線
有付費客人之後，先升級代管服務：Cloudflare Workers 付費版每月 5 美元起、Supabase Pro 每月 25 美元起，一樣不用顧機器。真的需要自訂環境才開 VM：照 Google 價目表換算，e2-small 每月約 12 美元、e2-medium 約 24 美元（不含硬碟和流量，各區域價格不同）。

選服務，先看它有沒有 CLI

這是很多人忽略、但很影響成本的觀念。上面推薦的每一樣都有官方 CLI，這是我挑材料的條件之一。讓 Claude Code 操作一個服務，有兩種方式：

看畫面操作 vs CLI 操作

看畫面操作（很花 Token）
Claude Code 要做的事：
1. 截圖整個畫面 → 花 Token
2. 分析圖片找按鈕位置 → 花 Token
3. 點擊按鈕 → 花 Token
4. 等頁面載入 → 花時間
5. 再截圖確認結果 → 花 Token
6. 分析結果圖片 → 花 Token

一個簡單的「部署網站」動作
＝6 個以上的步驟＝大量 Token

慢，Token 花得多
用 CLI 操作（省 Token）
Claude Code 要做的事：
1. 打一行指令

npx wrangler deploy

結束。

快，Token 花得少

差多少？依 Claude 官方文件的算法，一張全螢幕截圖要一千多到兩千多個 Token，畫面更大的可到四千多個，而一個動作常常要截好幾張。一行指令只有十幾個字。同一件事，看畫面做要花的 Token 多出一大截，也慢得多。CLI 還有一個好處：它做了什麼，指令都留在畫面上，你看得到。

CLI 對應服務 拿來做什麼 一行指令範例

選工具的鐵則
一個服務沒有 CLI、也沒有 API，Claude Code 就只能看畫面、點按鈕，Token 成本會暴增，也慢得多。所以選服務之前，先看它有沒有 CLI。

工具的先後順序：有官方 CLI 先用 CLI；沒有才裝 MCP（連接器）；操作網頁交給瀏覽器工具；都不行才用 Computer Use。每一種怎麼開、什麼時候該讓 Claude 直接操作畫面，在第十章 Claude Code 怎麼用。

這章帶走什麼

  • 先找再做：動手前上 GitHub 找現成的，看更新日期、星星數、授權條款
  • 不打包：純靜態頁面，存了什麼上線的就是什麼，你看得懂才守得住邊界
  • 一套組合：頁面放 Cloudflare，資料放 Supabase 或 D1，程式碼放 GitHub
  • Supabase 要守兩層：表要授權才會開放，開放的表都要開 RLS
  • 多數東西不用一直開著的機器：真的要，先在自己電腦跑，再考慮 VM，開了就要顧帳單
  • 選服務先看 CLI：有 CLI，Claude 做得快、花得少，你也看得到它做了什麼
跟 Claude 怎麼說
「做之前先用 gh 上 GitHub 找有沒有現成的，列給我看再決定。」
「用純 HTML、CSS、JS 做，不要有打包步驟。頁面放 Cloudflare，資料放 Supabase，每張表都開 RLS，要給頁面用的表才授權。程式碼推到 GitHub。」
「要用到新服務之前，先告訴我它有沒有官方 CLI、免費額度是多少。」
「這件事需不需要一台一直開著的機器？不需要的話，用 Workers 或排程做。」
